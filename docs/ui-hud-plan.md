# 游戏 UI / UX / HUD 探索：计划、路线图与里程碑

> 状态：2026-10-14 计划获批。进度记录见文末「进度」。

## Context

探索台已经能把画面风格拆成维度来组合，但游戏 UI 这一块几乎空着：
- 现在只有一个静态 DOM 样本（`src/ui/hud/Hud.tsx`）：状态栏写死 72%、小地图一个点、"E 打开宝箱"、一句对话；15 种皮肤写死在 `hud.css` 的 class 里，其中 7 种不读色板。
- **所有截图路径都看不到 HUD**：截图按钮、A|B 对比、收藏与扫描缩略图、QA 网格都只读 WebGL 画布；诊断视图（灰度 / 明度 / 剪影）也不作用于 HUD；画幅黑边挡不住 HUD；Godot 迁移包里没有任何 UI。
- 调研已经做了不少但没落地：`docs/survey/06-genre-camera-ui.md` 有 26 种 UI 风格（B1–B26）、16 个品类的界面需求（A1–A16）、设计 token 草案（C.2）、可读性检查（C.4）；案例库 200 条拆解里有约 50 条 UI 缺口，风格图谱里有 14 条 UI 相关缺口。

目标：像探索画面风格一样探索游戏 UI——拆成维度、选项是数据、能 A/B、能截图、能检查可读性、能迁移到 Godot。用户确认：16 个品类都要做，按 策略/建造 → 探索/RPG/动作 → 养成/解谜/叙事 → 卡牌/竞速/射击 的顺序；输入方式（键鼠 / 手柄 / 触屏）做成可切换维度；**从游戏库里找美术好评的游戏作参考**。2026-10-14 补充：每款游戏只归一个主品类，融合玩法写在说明里；UI 还要**按呈现内容分类**（不同游戏的 UI 显示的东西不一样）。

## 参考来源：一个大得多的 UI 参考库（研究轨，与实现并行）

UI 的选项不凭空设计：每个皮肤、布局、规则、UX 做法都挂上真实游戏作依据。目标是从现有 130 款获奖案例扩到 **约 500 款**有可见 UI 的参考作品，覆盖独立 + 3A + 手机，16 个品类每类至少 15 款。

**来源（按用途分）**
1. **"美术好评"名单（定义谁算参考）**
   - 已有：案例库 361 款，其中 130 款有 IGF 视觉艺术 / BAFTA 艺术成就 / TGA 最佳美术指导。
   - 新增奖项：GDC 选择奖 最佳视觉艺术、D.I.C.E. 杰出美术指导（1998 起）、Golden Joystick 最佳视觉设计、Apple Design Awards 视觉与图形（手机游戏）、Google Play 年度最佳——补上 3A 与手机。
   - Steam 信号：标签"美丽 / 绝美 / 风格化 / 手绘"等 ∩ 好评率 ≥ 90% 且评测数 ≥ 2,000。
2. **UI 专门的参考库（看 UI 长什么样）**
   - Game UI Database（1,341 款、55,000+ 张，按界面类型 / 品类 / 材质 / 布局分类）、Interface In Game（按元素：对话、背包、地图、设置、技能树、教程……）。
   - 只记链接与我们自己的笔记，不复制它们的截图（第三方截图有版权）；本地看图用 Steam 商店截图，和现有案例库一样"本地学习参考，不再分发"。
3. **玩家怎么评价这套 UI（UX 证据）**
   - Steam 公开评测接口（英文 + 简体中文）：统计每款提到"美术 / 画面 / art"的比例（美术好评率），以及提到"界面 / UI / 菜单 / 背包 / 字太小"的好评与抱怨，摘要成一两句（不整段引用）。这是"UX"部分最直接的证据：哪些做法玩家喜欢、哪些被骂。
   - 补充：现有市场研究数据（129 款 2026 新作）里 7 款提到美术或界面好用。
4. **从业者资料**：GDC 演讲与开发者访谈里讲 UI 的（如 Hades、Persona 5、Dead Space 叙事内 UI），在参考卡上注明出处。

**UI 参考卡**（每款一张，`src/content/uiRefs.json` + `docs/survey/07-ui-references.md`）：主品类 + 融合说明、**呈现内容**（出现了哪些界面类型与信息元素，各附截图出处）、美术好评证据（奖项 / 好评率）、皮肤类型（映射到皮肤清单，或标为新风格）、放置方式（四分法）、字体类别、UI 与世界的关系（同一媒介 / 刻意对比 / 极简无 HUD）、各界面场景（HUD / 菜单 / 背包 / 对话 / 地图）的做法、玩家对 UI 的评价、值得学的 UX 点、参考链接与本地截图。

**做法**：复用案例库的采集与核验流程（Steam 商店信息、截图下载、奖项名称匹配）；截图里的 UI 由子代理逐张拆解（和之前 200 条视觉拆解同样的做法，标注"画面推断"的置信度）；不调用 AI 生成。预计新增本地截图约 300–500 MB（`public/cases/<appid>/`）。网页搜索有每轮额度上限，奖项名单优先用维基百科与官方存档页直接抓取。

## 关键架构决定

**HUD 改为 Canvas2D 绘制，在后处理的 OUTPUT pass 里合成**（取代 DOM `<Hud/>`）。理由：
- 截图、A|B、扫描、收藏、QA 网格自动包含 HUD（`renderSync` 读的画布里就有它）；DOM 转图片（SVG foreignObject / html-to-image）是异步的，字体与 `backdrop-filter` 都画不出来，不可行。
- HUD 纹理按完整画布分辨率绘制，不受 `camera.pixelSize` 像素化影响；像素皮肤按设计分辨率（如 640×360）画、整数倍最近邻放大。
- 画幅黑边内排版；诊断视图可选择包含 HUD；CRT 弯曲自动作用于 HUD。
- 和探索台自己的 CSS 完全隔离（需求 §5.3）。
- 同一套 token 喂给绘制、Godot 导出、描述导出、对比度检查，不会出现四份不一致的实现。
- 先例：`Pipeline.ts` 里的 `OsdLayer`（录像带时间码）已经是"画布纹理 → 后处理合成"的做法。

**叙事内 UI 走美术管线**：世界里的招牌、霓虹字、背上的血条，用 `src/engine/sprites.ts` 的公告板 / 世界空间四边形，纹理由同一个绘制器画，所以会被描边、纸纹、辉光处理；屏幕叠加、空间内、元 UI 保持清晰。

**皮肤 = 预设 + 覆盖，用纯函数解析**：`resolveTheme(values) = 覆盖(跟随画面(皮肤预设, values), values)`。`hud.style` 的 id 保持不变，配方、收藏、localStorage、风格图谱里的 `hud.style` 都不受影响；覆盖参数默认值都是"跟随皮肤"。

## 数据模型（要点）

- `SkinTokens`：颜色表（每项"固定色 + 可选色板角色"）、字体角色（display / body / number / mono）、盒子样式（面板、内嵌、提示框、血条底与填充、按键、名牌、地图框、按钮五态）——字段形状对齐 Godot `StyleBoxFlat`（底、各边边框、圆角、切角、阴影、内边距、倾斜），额外效果（毛玻璃、双线、手绘抖动、九宫格、角饰）单独标记迁移难度；文字样式；血条形状；图标集；光标；动效；设计分辨率与整数缩放。
- `SkinDef`：id、对应调研编号 B1–B26、标签、说明、提示词、技术提示词、能力状态、迁移说明、tokens、性能开关。
- `LayoutDef`：控件实例列表（类型、放置方式、锚点/偏移/尺寸——对齐 Godot Control 锚点、挂接对象：玩家 / 最近兴趣点 / 全部兴趣点、数据绑定、各放置方式的变体）+ 该品类引用的可读性规则（A 节编号）+ 海报时刻（截图用的固定模拟时刻）。
- 控件注册：`registerWidget(type, { measure, paint, godot? })`。新增皮肤 / 控件 / 品类 = 加一条数据或一个文件。
- 兴趣点（POI）：`SceneDesc.pois?`（交互、拾取、NPC、敌人、目标、地标、出口、危险）+ `Item.tag?`；没有标注的场景自动推导（标签物件 → 小尺寸的 interactive 角色物件 → 光源 → 最高物件作地标 → 出生点 → 不足 3 个时补"示意"点）。

### 路线图 v3（2026-10-14 用户要求：大而全地探索 UI 风格，不再盯着一个样本游戏）

用户指出 v2 做完后"看起来只是在复刻一个游戏"。原因：样本内容只有一个虚构游戏"雪线旅人"（写死在 9 个文件里，所有品类布局都用同一套道具 / 台词 / 主角，M11 素材也是给它画的）；452 张参考卡平均只编码 5.3 个参数、一句笔记，是速写不是复刻；知识只存成"能调什么"（参数），没写成"为什么、什么时候这么调"（原则）；1,457 款美术好评候选只用了三成。用户要求三件事都做，而且大而全：① 设计原则总结；② 工具里讲道理；③ 样本内容按品类换；要复刻就系统地复刻大量好游戏的 UI / HUD。**手游的商城、奖励、抽卡、签到、首充、通行证等商业化界面不再学习与扩充**（已有代码保留，界面里收进"商业化（不再扩充）"折叠组，不进随机探索、原则总结与复刻库）。

## 风险

- **观感变化**：画布画不出 CSS 的椭圆圆角、`clip-path` 等细节，手绘皮肤改用抖动路径近似。M1 用参考图逐一对照。
- **性能**：高 DPR 下每帧上传 HUD 纹理的开销；只在内容变化时重绘、上限 30Hz；超预算时改为"静态层纹理 + 动态层实例化四边形"。
- **字体**：首帧时序靠 `pending` 集合 + 重绘解决；单文件构建（`file://`）下 FontFace 加载未验证；运行时拼出的文字可能超出子集（逐字回退 + 内容检查报警）。中文字体子集化需要新增开发依赖 `subset-font`（harfbuzz wasm）。
- **Godot**：`.tres` 的渐变纹理、倾斜等字段要在 4.7 上验证；验证脚本加成功标记前存在假通过风险。
- **组合爆炸**：26 皮肤 × 16 布局 × 4 放置方式 × 3 输入方式，只按单一维度出对照图，不跑全排列。
- **存档兼容**：`hud.style` id 不变，新参数取默认值，旧配方与收藏不受影响。
- **参考库规模**：约 500 款拆解靠子代理看截图，耗时长、属于"画面推断"；网页搜索每轮有额度，奖项名单优先直接抓维基百科与官方存档；Steam 截图只作本地学习，Game UI Database / Interface In Game 只记链接与笔记、不复制图片。

## 验证方式

- 每个里程碑：`npm run typecheck`、`npm run check:content`、`npm run build`；浏览器（launch 配置 `art-explorer-alt`，端口 5191）里用 `window.__gae.grid` 出对照图——M1 之后对照图自带 HUD。
- 确定性：同一参数两次 `renderSync` 结果相同（M5 起）。
- 参考库：`check:content` 校验 `uiRefs.json` 的字段、链接与截图文件存在，并输出"每种皮肤 / 每个品类 / 每种放置方式的参考数"，低于 3 的列为待补。
- 性能：统计面板记录 HUD 绘制与上传耗时。
- Godot：`npx tsx scripts/godot-validate.ts`（M4 起含皮肤变体与 HUD 成功标记），查看各变体的 `shot.png`。
- 文档：批准后把本计划存为 `docs/ui-hud-plan.md`，每个里程碑完成时更新状态；`docs/survey/06-genre-camera-ui.md` 补上叙事性四分法与 Godot Theme 对照。
