# 调研缺口与后续方向（Research Backlog）

这份清单记录撰写 `04-chinese-architecture-painting.md`、`05-palettes.md`（含 `data/palettes.json`）和 `06-genre-camera-ui.md` 时发现、但没能做完或没覆盖到的方向。

背景：本轮调研中途，所有 agent 共用的 **WebSearch 额度（每轮 200 次）用完了**。之后只能直接抓取已知 URL，有些条目因此停在"未核实"。

**优先级**
- **P0**：直接影响探索台核心体验或数据可信度，建议下一个里程碑处理。
- **P1**：明显提升覆盖面或质量。
- **P2**：长期扩展。

---

## P0：数据可信度与核心管线

| # | 缺口 | 为什么重要 | 建议下一步 |
|---|---|---|---|
| 1 | **中国传统色缺少权威来源**。现用的 zhongguose 526 色没有注明出处；其中 8 色 RGB 与 hex 自相矛盾，已剔除；故宫 384 色只有疑似取样量化的第三方转录 | 色板是"文化依据"最直观的部分，来源不清会削弱整个中式方向的可信度 | ① 购入或借阅《中国传统色：故宫里的色彩美学》，按书中 CMYK 用 ICC 配置（如 Japan Color 2001 Coated 或 GB/T 印刷标准）换算成 sRGB，录入为 `cn-gugong-384` 数据集，注明换算方法。② 给每个色样加 `provenance` 字段（`book-cmyk`、`site-hex`、`measured`）|
| 2 | **清式营造数值未核实**：举架序列、冲三翘四、面阔与柱高比、柱径、台明高、斗口 11 等；江南《营造法原》的发戗数值也未核实 | 屋顶生成器的默认参数依赖这些数，错了会让建筑"看着不对" | 找梁思成《清式营造则例》（1934）和《营造法原》的公开扫描本（版权状态需确认），把"各件权衡尺寸"表录成 JSON；同时用第 3 节的界画（黄楼图、龙池竞渡图、岳阳楼图）做目测校验 |
| 3 | **中式屋顶程序化生成原型**还停留在公式阶段（04 文档 1.2、1.3 的高度场 + 举折）| 这是中式场景的第一识别特征，也是最难"凑合"的部件 | 用 Three.js 实现 7 种屋顶加重檐和卷棚开关，导出 glTF，与故宫、苏州园林照片并排比较；验证翼角 s² 曲线的经验值 |
| 4 | **中国画非真实感渲染（NPR）的学术与工程现状**没做系统调研：笔触建模、水墨扩散、实时皴法纹理等 | 04 文档只给了概念映射，缺少可直接参考的算法和开源实现 | 检索 NPAR/Expressive、SIGGRAPH、Eurographics、CGF 上的 Chinese ink painting / sumi-e rendering / brush stroke 论文，以及 GitHub 上的开源 shader。整理成"算法 → 效果 → 成本 → Three.js/Godot 可移植性"表 |
| 5 | **从 CC0 名画提取"实测色板"**。现有中国色组是按色名编配的，不是从画面取色 | 用户想要"像《千里江山图》"，最可靠的是从真实画面统计主色 | 用台北故宫 CC0 图（明皇幸蜀图、早春图、汉宫春晓等）和 Met、Cleveland 的 CC0 图，在 OKLab 空间做 k-means 或中位切分，按区域（山顶、山腰、绢底）采样，生成 `measured` 色组。注意北京故宫的图仅可浏览，不能用来做数据 |
| 6 | **品类镜头参数大多是经验值**（06 文档 A17 表）。射击游戏 FOV、Celeste 房间切换等若干条未核实 | 镜头预设是"同一场景换品类"体验的基础 | 对代表作截图做相机反求：用灭点和已知物体尺寸估算 FOV 和俯仰。也可以查官方设置菜单或开发者访谈，逐条把"经验值"升级为"已测" |

## P1：覆盖面扩展

| # | 缺口 | 为什么重要 | 建议下一步 |
|---|---|---|---|
| 7 | **西南、西北与少数民族建筑**：藏式碉房与寺院、羌族碉楼、傣族竹楼、侗族鼓楼与风雨桥、一颗印、蒙古包、维吾尔阿以旺；配套色组缺失（04 文档 1.11 已标"待补"）| 中国题材游戏常用这些地区做"异域关卡"，现在只有汉地主流类型 | 每个类型按 04 文档 1.9 的表格补齐：平面、剪影、材质、色彩、模块清单；并补 `cn-southwest`、`cn-tibet`、`cn-loess` 色组 |
| 8 | **中式室内与家具**：明式家具比例、屏风、博古架、藻井、天花彩画 | 叙事、解谜、生活类品类大量发生在室内；目前只覆盖外观 | 整理明式家具的典型尺寸和构件名，参考王世襄《明式家具研究》（需核实版权和可得性），以及故宫藏品页 |
| 9 | **中式场景类型库**：宋代街市（清明上河图）、码头、驿站、客栈、佛寺（伽蓝布局）、道观、陵墓、城墙与城门、军营、科举贡院、夜市、灯会 | 武侠、仙侠、历史题材最常用的就是这些场景，探索台需要能"一键切场景" | 每个场景写一页"空间语法卡"：布局、关键地标、尺度、可交互物、参考画作或照片 |
| 10 | **历代服饰与角色**：汉、唐、宋、明服饰轮廓，发式，甲胄；与和服、韩服的区分 | 角色是画面焦点，服饰错乱是中式题材最常被批评的问题 | 汇总各博物馆服饰文物和《中国古代服饰研究》（沈从文）等资料的轮廓特征，做成"剪影对照表"，并补充 04 文档第 4 节的避坑清单 |
| 11 | **中国传统工艺作为渲染风格**：青花瓷（蓝白釉下彩）、景泰蓝（掐丝珐琅）、漆器（剔红）、唐三彩、皮影、剪纸、刺绣、木版年画（已有色组，缺渲染规则）| 这些是区别于"日式水墨"的独特视觉语言，适合做整屏风格或材质 | 为每种工艺写"视觉机制 → shader 方案"条目，可以并入 `01-style-taxonomy.md` 第 16 组，或在 04 文档后续版本中新增 |
| 12 | **日韩与其他亚洲文化的同等深度资料**：韩国丹青、五方色缺少有来源的 hex；日本只有 3 套色组；东南亚（泰、高棉、越）、南亚（莫卧儿细密画）、伊斯兰几何纹样都只有分类条目 | 用户要求覆盖要大而全；混搭问题也需要对照资料来避免 | 优先找韩国官方或学术来源的传统色标准（如韩国文化财厅的丹青色彩研究，en.wikipedia Dancheong 条目引用了 Song et al. 2018 的丹青色彩论文），再按 05 文档格式录入 |
| 13 | **天气与季节的中国画表现**：雪景（江行初雪图、渔村小雪图）、雨景（米氏云山）、四时预设（林泉高致"春山如笑"等）| 天气是氛围的主要来源，04 文档只给了四时的文字规则 | 为雪、雨、雾、夜分别设计水墨或青绿版本的参数，用第 3 节作品做对照验收 |
| 14 | **UI 风格的实物样例与字体授权**：06 文档有 26 种 UI 风格，部分代表游戏未核实；中文书法、宋体、楷体字体的可商用授权没有整理 | UI 皮肤要能直接落地，字体授权是上线风险 | 整理一份开源中文字体清单（如思源宋体、思源黑体、霞鹜文楷等 OFL 字体，许可需逐一核实），并为每种 UI 风格做一个 HTML/CSS 小样组件 |

## P2：工具化与长期方向

| # | 缺口 | 为什么重要 | 建议下一步 |
|---|---|---|---|
| 15 | **参考图管线**：台北故宫网站会用 Cloudflare 拦截脚本请求；Met 旧 search API 已于 2026-10-01 停用，需改用 `/v1.1/search`（博物馆子代理报告） | "参考画与实时画面并排"的功能需要稳定取图 | 优先走 IIIF（台北故宫提供）和 Met、Cleveland 的官方 API；本地缓存时保存许可证字段，禁止把仅可浏览的图打包进产品 |
| 16 | **调色板工具**：OKLab 量化、有序或误差扩散抖动、Riso 叠印模拟、NES 与 C64 多版本色值对照 | 05 文档已给数据，缺少交互工具 | 实现 `palette-quantize` 后处理（WebGL 与 Godot 两版）和"同机多版本"切换 |
| 17 | **可读性自动检查**：灰度、模糊、色盲模拟（Machado 2009）、剪影检查、对比度统计 | 06 文档 C.4 给了检查清单，需要真正跑起来 | 在探索台加"检查模式"面板，输出对比度数值和热力图；对中式色组跑一遍。青绿配朱红对红绿色弱用户可能有风险 |
| 18 | **Godot 移植层**：中国画渲染的 shader（GLSL）到 Godot shading language 的对照，以及描边、笔触网格方案在 Godot 4 的可行性 | 需求文档要求"便于迁移到 Godot" | 选 3 个代表 shader（墨色阶、米点贴花、纸纹湿边）做双端实现和性能对比 |
| 19 | **艺术运动色板缺少权威值**：De Stijl、Memphis 是近似值；Bauhaus 用的是像素画家的诠释版；Riso 的 hex 是社区按 Pantone 换算的 | 想要"准确复刻"运动风格时，需要知道哪些是推测 | 查博物馆（MoMA、Tate、Gemeentemuseum）的作品技术分析；Riso 联系官方或用 Pantone 官方 sRGB 值重算 |
| 20 | **文化与合规敏感点**：皇家与宗教符号（龙纹等级、佛像）的使用，真实印章、题跋的伪造风险，以及面向中国大陆发行时的内容审查习惯（如骷髅、血液表现）| 影响能否上线，以及文化尊重 | 单独做一页"文化与合规注意事项"，资料来源需谨慎核实，标注地区差异 |
| 21 | **Web 端性能预算**：笔触网格、多层叠加、洇散模拟都比较重 | 探索台是网页工具，可能在核显或手机上运行 | 给每个中国画预设标注 GPU 成本等级，提供低配回退（例如只用后处理描边加纸纹）|
