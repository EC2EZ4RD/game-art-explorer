# 品类镜头、可读性与 UI 风格调研（Genre Camera / Readability / UI Skins）

这份文档给"美术风格探索台"补三块内容。A 部分按 16 个游戏品类，整理典型镜头方案、可读性规则、常见美术陷阱，以及工具里可以直接实现的"玩法测试片段"(gameplay test snippet)，最后附一张镜头预设参数总表。B 部分整理 26 种 UI 风格，每种写清定义、CSS 特征、代表游戏、适用场景和陷阱。C 部分给出把"品类镜头预设 + UI 皮肤"做成工具参数的 JSON 草案，以及一套可读性检查清单。开头的第 0 部分是三部分共用的基础：投影数学、FOV 换算、跟随行为术语和通用可读性原则。

**图例**
- **[n]**：文末来源编号。列出的页面都实际打开读过；只能读到转引或摘要的，在来源列表里注明。
- **经验值**：作者按行业惯例给的起步参数（rule-of-thumb），不是某款游戏的实测值或官方数据。只用作工具默认值，要按项目调。
- **未核实**：有一定依据（社区讨论、检索摘要、游玩印象），但这次没找到可靠的一手来源。
- **公开常识**：某游戏用哪种镜头这类玩过就能确认的事实（例如"《炉石传说》是固定俯视牌桌"），不逐条标来源。
- **角度约定**：俯仰角 (pitch) 指视线相对水平面向下的角度，0° 是平视，90° 是正俯视。FOV 默认指**垂直视场角** (vertical FOV)，因为 Three.js 的 `PerspectiveCamera.fov` 和 Godot `Camera3D.fov`（默认 `KEEP_HEIGHT`）都按垂直方向定义 [15][12]。
- **单位**：1 单位 = 1 米，角色身高按 1.8 m 算。

## 0. 共用基础

### 0.1 投影方式与等轴角度

| 投影 | 定义 | 相机设置 | 典型用途 |
|---|---|---|---|
| 透视 (Perspective) | 近大远小，有消失点 | `PerspectiveCamera(fov)` / Godot `PROJECTION_PERSPECTIVE` [12] | 第一/第三人称、竞速、大部分 3D |
| 正交 (Orthographic) | 物体屏幕尺寸和距离无关 | `OrthographicCamera` / Godot `PROJECTION_ORTHOGONAL`，`size` 是可视高度（米，`KEEP_HEIGHT` 时）[12] | 2D/2.5D、等轴、工厂、解谜 |
| 真等轴 (True isometric) | 正交；偏航 45°，俯仰 ≈ 35.264°（= arctan(sin 45°)）；三根轴在屏幕上互成 120° [11] | 相机放在 (d, d, d) 方向看原点 | 视错觉解谜（纪念碑谷式）、微缩场景 |
| 2:1 二等轴 (Dimetric 2:1) | 正交；偏航 45°，俯仰 30°；地面边线斜率 arctan(0.5) ≈ 26.565°，就是像素画里"横 2 竖 1"的台阶线 [11] | 见下方代码 | 像素"等轴"游戏的主流。维基指出游戏里叫"等轴"的大多其实是二等轴 [11] |
| 三等轴 (Trimetric) | 三根轴的缩放各不相同 | 偏航不取 45° | Fallout (1997)、SimCity 4 [11] |
| 斜投影 (Oblique / 正面 + 顶面) | 物体正面不变形，顶面斜切露出 | 2D 美术画法，3D 里用正交相机 + 小俯仰近似 | Ultima Online [11]；像素俯视 RPG/种田游戏（公开常识） |
| 窄 FOV 透视（"伪正交"） | 远距离 + 小 FOV（15°–30°，经验值），保留轻微近大远小 | 透视相机拉远 | 想要"等轴感"，又要保留透视雾、景深和体积感的 3D 作品 |

**推导**（作者自算，结果和 [11] 一致）：正交相机偏航 45° 时，地面坐标轴投到屏幕上的斜率 = sin(俯仰角)。俯仰 30° 时 sin = 0.5，边线角 arctan(0.5) = 26.565°，这就是 2:1 像素线。俯仰 35.264° 时 sin = tan 30°，边线角正好是 30°，这就是真等轴。

```js
// Three.js：真等轴（俯仰 35.264°、偏航 45°）
const h = 12;                                   // 正交可视高度（米）
const cam = new THREE.OrthographicCamera(-h*aspect/2, h*aspect/2, h/2, -h/2, 0.1, 500);
cam.position.set(50, 50, 50); cam.lookAt(0, 0, 0); // (d,d,d) 方向 → atan(1/√2) = 35.264°

// 2:1 二等轴：俯仰 30°
const p = THREE.MathUtils.degToRad(30), y = Math.PI / 4, d = 50;
cam.position.set(Math.cos(p)*Math.sin(y), Math.sin(p), Math.cos(p)*Math.cos(y)).multiplyScalar(d);
cam.lookAt(0, 0, 0);
// Godot 对应：projection = PROJECTION_ORTHOGONAL; size = 12; rotation_degrees = Vector3(-30, 45, 0)
```

### 0.2 FOV 换算与屏幕尺寸

- 水平/垂直换算：`hFOV = 2·atan(tan(vFOV/2)·aspect)`。Godot 用 `keep_aspect` 决定 `fov` 锁哪根轴，默认 `KEEP_HEIGHT`（Hor+：屏幕越宽看到越多）[12]；Three.js 的 `fov` 固定是垂直方向，默认 50° [15]。
- 16:9 下的常用对照（作者计算）：

| 垂直 vFOV | 16:9 水平 hFOV | 备注 |
|---|---|---|
| 30° | 50.9° | 等轴感动作游戏、策略 |
| 50° | 79.3° | Three.js 默认 [15] |
| 60° | 91.5° | 第三人称常用（经验值） |
| 70° | 102.4° | 第一人称常用（经验值） |
| 70.5° | 103° | 水平 103° 的第一人称射击就是这个值 |
| 75° | 107.5° | Godot 默认 [12] |

- **屏幕像素高**：透视下 `像素高 ≈ H / (2·d·tan(vFOV/2)) × 视口像素高`；正交下 `像素高 ≈ H / 正交可视高度 × 视口像素高`。例：vFOV 70.5°、1080p 下，50 m 外 1.8 m 高的角色约 27 px。工具可以用这个公式做"距离可读性"检查（见 C 部分）。

### 0.3 跟随行为术语

2D 部分以 Itay Keren 的《Scroll Back》为准。它是 GDC 2015 独立游戏峰会演讲的扩写版，作者说明这些分类名是他自己归纳的，不是业界统一术语 [1][2]。3D 部分以 Unity Cinemachine 和 Godot 文档为准。

| 术语 | 含义 | 代表作 / 引擎对应 |
|---|---|---|
| 位置锁定 (position-locking) | 镜头死死跟着角色 | Rally-X、泰拉瑞亚 [1] |
| 摄像机窗口 / 死区 (camera-window / dead zone) | 角色在框内移动镜头不动，碰到框边才推镜头 | 超级马里奥兄弟 [1]；Cinemachine Dead Zone [16]；Godot `Camera2D.drag_*_enabled` + 拖拽边距（默认 0.2，1 表示角色到屏幕边缘才移动）[13] |
| 软区 + 阻尼 (soft zone + damping) | 目标进入软区后镜头按阻尼时间把它拉回死区；阻尼可按轴分别设置 | Cinemachine Position Composer [16] |
| 硬边界 (hard limits / limits) | 目标不能离开的屏幕区域，或镜头不能越过的世界边界 | Cinemachine Hard Limits [16]；Godot `limit_left/right/top/bottom` [13] |
| 平台吸附 (platform-snapping) | 跳跃和空中时镜头纵向不动，落地后才平滑吸附到新平台高度 | 超级马里奥世界、雷曼、索尼克 [1] |
| 双侧前置聚焦 (dual-forward-focus) | 角色两侧各一个前方锚点，转身越过阈值才切换（马里奥世界），或按移动速度慢慢移过去（洞窟物语） | 超级马里奥世界、洞窟物语 [1] |
| 前瞻 (look-ahead / projected-focus) | 按速度预测几秒后的位置并提前偏移 | Cinemachine Lookahead Time / Smoothing / Ignore Y [16]；雷堤康的秘密、Mushroom 11 [1] |
| 插值平滑 (lerp-smoothing) | 每帧按固定比例逼近目标。缺点是高速角色可能先冲到屏幕边缘 | 大金刚国度、超级食肉男孩 [1]；Godot `position_smoothing_speed`（默认 5）[13] |
| 物理平滑 (physics-smoothing) | 镜头有加速、减速，甚至会冲过目标再回拉 | [1] |
| 区域锚点 (region-based anchors) | 每个区域或房间各自设锚点、边界和缩放 | 超级马里奥世界、大金刚国度、FEZ [1] |
| 线索聚焦 (cue-focus) | 镜头被 Boss、关键物等"吸引点"拉偏 | Limbo 等 [1] |
| 缩放适配 / 位置均值 (zoom-to-fit / position-averaging) | 让多个目标同时入画；多人游戏取平均位置 | 缩放适配：耀西故事、任天堂明星大乱斗；位置均值：不再孤独 Never Alone [1] |
| 碰撞回缩 (spring arm) | 沿镜头方向发射射线或形状，碰到障碍就把相机拉近 | Godot `SpringArm3D`（`spring_length`、`margin`、`shape`）[14] |
| 锁定 (lock-on / Z-targeting) | 镜头跟随锁定目标，角色始终面向目标 | 塞尔达传说 时之笛首创并普及，后来成为 3D 动作冒险的通用元素 [17] |

### 0.4 3D 镜头的常见错误（节选，适合当工具里的自动检查项）

John Nesky 是《风之旅人》(Journey) 的动态镜头设计师。他在 GDC 2014 讲了"50 个镜头错误"，涵盖让玩家迷失方向、难以判断距离、视线被遮挡、引起晕动等问题 [3][4]。完整编号来自一份二手转述 [5]，下面挑出和"风格评估"关系最大的几条：

| # | 错误 | 工具里的对应检查 |
|---|---|---|
| 4/5 | 默认距离经常被遮挡视线；障碍从侧面挡住视线 | 弹簧臂开关、遮挡率统计 |
| 13 | 近裁剪面切进角色 | 贴墙测试 |
| 15/16 | 仰拍和常规视角用同一个 FOV；俯仰、距离、FOV 各调各的 | 镜头预设里把三者做成一条曲线联动 |
| 20 | 越过 180° 轴线 | 叙事镜头测试 |
| 24 | 距离难以判断 | 尺度参照物（门、人） |
| 41/42 | FOV 太小；FOV 变化太快 | FOV 下限和变化速率上限 |
| 43/44/45 | 震屏过度；镜头随步伐上下晃；角色跳跃时镜头上下移动 | 震屏强度上限、头部晃动开关、平台吸附 |
| 49 | 只在很窄的人群里测试 | 色盲、晕动、低视力检查 |

> Mark Haigh-Hutchinson 的《Real-Time Cameras》(2009) 是系统讲游戏镜头的专著，作者负责过《银河战士 Prime》和续作《Echoes》的镜头系统与角色操控 [48]。本次只读到出版社的书目介绍，没读到正文，书中具体规则**未核实**。

### 0.5 通用可读性原则

1. **读取层级 (read hierarchy)**：TF2 要求玩家在各种距离和视角下迅速认出"敌还是友 → 什么职业 → 拿什么武器"，分别用颜色、剪影（体型比例、武器、鞋帽、衣褶）和武器位置来解决。全身对比度最高的地方放在胸口（持枪处），明度从脚（暗）到胸口（亮）渐变 [6][7]。
2. **剪影先行**：TF2 的角色流程是"剪影 → 内部形状 → 模型表（只用剪影解决设计问题）→ 3D 模型" [7]。Riot 认为剪影是辨认英雄最重要的因素：每个英雄要有一个独有的主特征，剪影还要能看出力量来源（例如拿弓就是远程）和朝向 [9]。
3. **环境让位给角色**：TF2 的环境原则是明度对比、简单形体、减少纹理和几何噪声、减少重复，并且环境整体比角色降饱和 [6][8]。照片写实的高频细节会压过设计 [6]。
4. **中立物体用第三种色相**：TF2 的血包用绿/青色，危险的列车场闸门用黄色，都避开红蓝阵营色。中立物体的饱和度也更高，好在降饱和的环境里跳出来 [6]。
5. **视觉权重 = 玩法权重**：Riot 要求技能吸引的注意力和它的重要性相当。视觉噪声叠加得很快，团战里会让人反应不过来 [9]。特效的主元素（形状）要一眼可读，次元素只负责主题氛围；以中间明度为主，高饱和留给焦点；特效时间要短 [10]。
6. **投射物静止时也要能看出方向** [9]。
7. **光引导与雾分层**：L4D 发现玩家倾向跟着光走。在暗处用浅色雾、用粒子衬托中景感染者的剪影。早期截图对比区域太多，后来简化了布光 [8]。
8. **颜色不单独承载信息**：颜色要配合符号、图案或形状。双阵营推荐橙对蓝，同时拉开明度（例如浅蓝对深橙），并提供三种色盲预设。红绿色觉障碍约占男性的 8–10% [32]。
9. **UI 与世界分离**：WCAG 要求正文对比度 ≥ 4.5:1，大字 ≥ 3:1，UI 组件和图形 ≥ 3:1 [34]。UI 动画不要遮挡战斗：Persona 5 早期 UI 动画太多盖住了画面，后来减弱了 [47]。
10. **清晰优先**：Into the Breach 的 Justin Ma 说过，"we would sacrifice cool ideas for the sake of clarity every time" [27]。

## A. 16 个品类：镜头、可读性、陷阱、测试片段

> 每个品类的四块内容依次是：①镜头方案表（参数除注明来源的都是经验值）②可读性规则 ③常见美术陷阱 ④测试片段（工具可以实现的最小场景 + 检查项）。

### A1 探索与冒险（Exploration & Adventure）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 第三人称自由轨道 (free orbit) | 透视；俯仰 10°–20°；距离 4–6 m；vFOV 50°–60° | 玩家绕角色转镜头；跑动时自动回到身后（Nesky 把"跑动时不调偏航"列为错误 [5]）；弹簧臂碰撞 [14]；跳跃时纵向不跟 | 塞尔达传说 旷野之息、超级马里奥 奥德赛（公开常识）；风之旅人（动态镜头 [3]） |
| ② 第一人称 | 透视；vFOV 60°–75° | 无跟随；转向可加轻微惯性；头部晃动可关 | Firewatch、Outer Wilds（公开常识） |
| ③ 固定斜俯视 (fixed high-angle) | 透视（偏窄）；俯仰 40°–55°；距离 12–20 m；vFOV 25°–35° | 不可旋转；死区 + 平滑跟随；按区域换角度（区域锚点 [1]） | Tunic、塞尔达传说 织梦岛 (2019)（公开常识） |

**可读性规则**
- 地标 (landmark) 要在天空或远景前形成清晰剪影，明度和周围拉开；远景用大气透视（降对比、偏冷）分层。
- 用光、路面明度和饱和度引路（玩家倾向跟着光走 [8]）。
- 可交互物比环境更饱和，或带边缘光、闪点。采集品用环境里没有的色相（TF2 中立物体原则 [6]）。
- 植被等高频细节压在中间明度，不跟角色和拾取物抢对比 [6]。

**常见美术陷阱**
- 草叶和碎石贴图太"花"，远处糊成噪点，拾取物被淹没。
- 雾、泛光、景深把地标洗白。
- 整个区域同一个明度段，"哪儿都一样"，容易迷路。
- 自由轨道下，画面中心长期是角色**背面**，背部设计（披风、背包）却常被忽略（经验值观察）。

**测试片段**
1. 「草丛拾取物」：密集植被，镜头①距离 5 m，角色前方 15 m 放 1 个拾取物和 3 个敌人。开灰度 + 模糊（半径约视口高的 0.5%），检查拾取物和周围的亮度比 ≥ 3:1（借 WCAG 非文本对比 [34] 当参考阈值）。
2. 「地标剪影」：200 m 外放一座塔，依次切晨、午、黄昏、雾四种光照，在剪影模式下检查塔的轮廓是否还和天空分得开。
3. 「贴墙转身」：角色贴墙转 180°，检查弹簧臂回缩时是否穿模、近裁剪面是否切到角色（Nesky #13 [5]）。

### A2 动作与 Roguelite（Action & Roguelite）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 固定斜俯视（等轴感） | 窄 FOV 透视或正交；俯仰 45°–60°；地面可视宽 20–30 m；vFOV 25°–35° | 硬跟随 + 小死区；朝移动或瞄准方向少量前瞻；不旋转 | Hades（等轴视角 [28]）；暗黑破坏神 IV：玩家普遍抱怨镜头太近，找不到怪、挨屏外攻击，2024 年第 4 赛季加了更远的档位 [25] |
| ② 第三人称 + 锁定 | 透视；俯仰 10°–20°；距离 4–7 m（打大型 Boss 时拉远）；vFOV 50°–60° | 轨道 + 锁定，锁定时取景"玩家–目标"连线（Z 注目体系 [17]） | 黑暗之魂、艾尔登法环、怪物猎人：世界（公开常识） |
| ③ 越肩射击式 | 见 A4 ② | 越肩 + 瞄准缩放 | Risk of Rain 2、Returnal（公开常识） |

**可读性规则**
- 敌方攻击前摇 (telegraph) 要比玩家自己的特效更显眼：玩家特效降低亮度和不透明度，把注意力留给威胁（Riot：最重要的东西最吸睛 [9]）。
- 地面范围指示以边缘为主元素，内部只做淡填充（特效主次元素 [10]）。
- 敌我弹幕用形状 + 色相 + 明度三重编码，不能只靠颜色 [32]。
- 角色在任何地面材质上都保持最高的明度对比，必要时加描边或脚下光圈。
- 投射物静止时也能看出方向 [9]。

**常见美术陷阱**
- 泛光加叠加混合 (additive) 粒子层层重叠，整屏发白（overdraw），敌弹被吞掉。
- 地砖纹理太细碎，和弹幕"同频"。
- 镜头太近（暗黑 IV 的教训 [25]），或太远，角色不到 40 px 高（经验值）。
- 怪物配色和地面同色系。

**测试片段**
1. 「弹幕洪水」：镜头①俯仰 55°、vFOV 30°、距离 22 m；25 个敌人 + 40 发敌弹 + 玩家技能全开。在灰度下检查敌弹能否和玩家特效区分（明度或形状至少一项独立）。
2. 「地面预警」：同一个 AoE 圈放在 5 种地面材质上，测圈边缘和地面的亮度比。
3. 「色盲弹幕」：在红绿两种色盲模拟下，检查红色敌弹和绿色治疗球是否还分得开。

### A3 横版平台（Side-scrolling Platformer）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 2D 正交 + 窗口 / 平台吸附 | 正交；俯仰 0°；可视高度 10–14 m（角色约占屏高 1/6–1/8，经验值） | 横向：摄像机窗口或双侧前置聚焦；纵向：落地才吸附 [1]；Godot 用拖拽边距 + 平滑实现 [13] | 超级马里奥兄弟（窗口）、超级马里奥世界（平台吸附 + 双侧前置）[1]；大金刚国度（插值平滑）[1] |
| ② 房间 / 区域锚点 | 正交；每个房间各设边界和缩放 | 房间内跟随，出房间时过渡 | FEZ、Mushroom 11 [1]；Celeste 以房间为单位（社区复刻讨论按房间设边界和缩放 [31]；过渡方式和参数**未核实**）；空洞骑士（区域锁定，公开常识） |
| ③ 2.5D 透视侧视 | 透视；vFOV 20°–35°；距离拉远以减小畸变 | 同①，视差来自真实深度 | Trine、小小梦魇（公开常识） |

**可读性规则**
- 能站的表面要有最清楚的边：平台顶面一条高亮"可踩边"。
- 分前景、玩法层、背景三层：玩法层对比最高；背景降饱和、降对比、向天空色靠；前景遮挡物做半透明或剪影。
- 危险物（尖刺、岩浆）统一用高饱和警戒色 + 尖锐形状。
- 角色朝向和动作帧在小尺寸下也能看清。

**常见美术陷阱**
- 背景装饰长得像平台（"假平台"）。
- 前景草丛或柱子挡住角色。
- 像素画在非整数缩放或亚像素滚动时闪烁，要做像素对齐 (pixel snapping)。
- 视差层速度差太大，引起晕眩。

**测试片段**
1. 「假平台」：生成 5 个真平台和 5 个同形状的背景装饰，在剪影 + 灰度下检查真平台顶边是否比装饰至少亮一个明度档（1 档约 10% 亮度，经验值）。
2. 「窗口跟随」：开启宽 20% 屏的窗口 + 平台吸附，检查跳跃时镜头纵向位移为 0（马里奥世界式）。
3. 「像素抖动」：以 0.37 px/帧慢速滚动，检查像素纹理是否闪烁。

### A4 第一/第三人称射击（FPS / TPS）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 第一人称 | 透视；默认 vFOV 70°–75°（16:9 下 hFOV 约 102°–107°），提供 60°–90° 滑条；武器模型 (viewmodel) 单独用 50°–60° | 无；后坐力、镜头抖动设上限 | Minecraft 默认 70°，可调 30–110 [22]（是否按垂直轴**未核实**）。Valorant 固定水平 103°、Overwatch 80–103 可调、CS2 的 fov 90 按 4:3 基准（16:9 下约 106°），这些来自媒体攻略的检索摘要，**未核实** |
| ② 第三人称越肩 (over-the-shoulder) | 透视；俯仰 0°–10°；距离 2.5–4 m；肩部偏移 0.5–0.8 m；vFOV 55°–65°，瞄准时缩到 40°–45° | 弹簧臂碰撞 [14]；左右肩切换 | 战争机器、堡垒之夜（公开常识）；死亡空间（第三人称 + 全叙事内 UI [20]） |

**可读性规则**
- 按 TF2 的读取层级：阵营色 → 剪影 → 武器，胸口对比最高 [6][7]。
- 环境整体比角色降饱和 [8]。
- 敌人描边或高亮颜色让玩家自选（GAG 建议团队色、准星色可自定义 [32]）。
- 准星用双色（亮芯 + 暗边），在任何背景上都可见。
- 枪口火光和烟雾要短促，不要长时间挡视线（同 Riot"特效要短" [10]）。

**常见美术陷阱**
- 写实植被伪装加上过黑的暗部，敌人等于"隐身"。TF2 当年专门避开照片写实，就是为了可读性 [6]。
- 扫描贴图细节太密，远处角色糊进背景。
- 皮肤或外观改变了主剪影。Riot 规定任何皮肤都不能去掉或大改主剪影特征 [9]。
- 武器模型太大，挡住画面。

**测试片段**
1. 「三背景阵列」：在亮墙、暗走廊、植被三种背景前，分别在 10/25/50 m 放红蓝两队角色。计算剪影和背景局部的亮度比，并显示屏幕像素高（50 m、vFOV 70°、1080p 下约 27 px）。
2. 「队伍色盲」：在红绿色盲模拟下比较红/蓝和橙/蓝两套方案（GAG 推荐橙蓝 [32]）。
3. 「烟雾遮挡」：烟雾弹 + 连续枪口火光下，测准星和敌人剪影的可见性。

### A5 角色扮演（RPG）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 战术俯视（可旋转缩放） | 透视；俯仰 45°–65°；距离 12–30 m；vFOV 35°–45° | 平移 + 旋转 + 缩放；缩放时俯仰联动 | 博德之门 3（公开常识）；神界：原罪（鸟瞰透视 [11]） |
| ② 固定等轴 | 正交或窄 FOV 透视；俯仰 30°–45° | 硬跟随或边缘卷动；不旋转 | 暗黑破坏神 (1996，固定等轴 2D [11])；极乐迪斯科、永恒之柱（公开常识） |
| ③ 第三人称动作 RPG | 同 A2 ② | 轨道 + 锁定 | 巫师 3、最终幻想 VII 重制版（公开常识） |

**可读性规则**
- 职业、阵营剪影的做法同 TF2 [7]；队友和敌人脚下用不同形状的光圈区分。
- 战利品稀有度色阶（白/绿/蓝/紫/橙，暗黑类惯例，公开常识）要配合图标边框形状或粗细，不能只靠颜色 [32]。
- 提供"高亮键"：按住时显示所有可交互物的轮廓。
- 任务 NPC 和路人分开：任务标记 + 更高饱和的服装。

**常见美术陷阱**
- 环境细节过密，俯视时角色只有 40–60 px 高，装备细节全浪费（经验值）。
- 稀有度颜色和技能元素色（火红、冰蓝、毒绿）撞色。
- 等轴下高低层看不出来。

**测试片段**
1. 「俯视派对」：俯仰 55°、距离 18 m；4 名队友、6 个敌人、10 个可拾取物。分别关闭和打开高亮，记录能辨认的对象数量差。
2. 「稀有度色盲」：5 档稀有度图标在三种色盲模拟下两两比较。
3. 「层高」：两层平台 + 楼梯，灰度下判断谁高谁低。

### A6 解谜与侦探（Puzzle & Detective）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 第一人称 | 透视；vFOV 60°–70° | 无；检视物体时切近景 | 见证者 (The Witness)（公开常识）；奥伯拉丁的回归（第一人称 [29]） |
| ② 正交等轴 / 微缩场景 | 正交；真等轴或 2:1；可视高度 8–14 m；90° 档位旋转 | 固定或轨道 | 纪念碑谷（视错觉依赖正交，公开常识）；奇诺比奥队长 寻宝之旅（公开常识） |
| ③ 2D 桌面 / 界面式 | 正交 2D | 无 | 她的故事 (Her Story)、请出示证件 (Papers, Please)（公开常识） |

**可读性规则**
- 线索要"能被发现但不扎眼"：统一一套"可检查"的视觉语言，例如所有可检查物都有同色微光，或靠近时才出现提示。
- 同屏真线索 3–5 个左右，其余是干扰物（经验值）。
- 风格化后处理一定要做运动测试：《奥伯拉丁的回归》的 1-bit 抖动画面全屏运动时会让玩家晕动，作者因此改了渲染，加入类似运动模糊的处理 [29]。

**常见美术陷阱**
- "像素猎杀" (pixel hunting)：关键线索太小，或和背景同明度。
- 透视畸变破坏了正交视错觉的构图。
- 抖动、描线、纸纹这类滤镜把小字和小符号吃掉。

**测试片段**
1. 「书桌 30 件」：桌上 30 件道具，其中 3 件是线索。在模糊测试下检查线索剪影是否仍然独特。
2. 「抖动游动」：开 1-bit / 有序抖动后处理，镜头以 90°/s 转动，检查抖动图案是否在屏幕上"游动"（应锁在物体空间，经验值）。
3. 「正交对齐」：真等轴正交下，两根在 3D 里并不相连的梁，在屏幕上应该完美对齐（错觉测试）。

### A7 恐怖与悬疑（Horror & Suspense）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 固定机位 (fixed cameras) | 透视；每个房间若干机位 | 按触发区切机位；切换时保持操作方向（Nesky #18：切镜头不应重映射方向 [5]） | 生化危机 (1996)：固定机位 + 预渲染背景 + 坦克式操作。三上真司起初担心固定视角削弱代入感，但预渲染背景能在 PS1 上给出更多细节 [18] |
| ② 近距越肩 | 透视；距离 1.5–2.5 m；vFOV 50°–60° | 狭窄空间靠弹簧臂回缩 | 生化危机 4（公开常识）；死亡空间 [20] |
| ③ 第一人称 | 透视；vFOV 60°–70° | 头部晃动可关 | 失忆症、逃生（公开常识） |

寂静岭用距离雾和黑暗遮掩主机性能、避免物体突然出现，同时制造氛围；脚本区域里镜头会切到别的角度制造戏剧效果 [19]。

**可读性规则**
- 暗不等于看不清：威胁要放在更亮的背景（浅色雾、粒子、光源）前形成剪影。L4D 在暗处用浅色雾、用粒子衬托中景感染者 [8]。
- 玩家自己就是光源：L4D 把手电绑在武器上，换弹、推击时光束会晃，鼓励队友配合 [8]。
- 用光导航；可交互物用微弱高光，不用 HUD 图标 [8]。
- 对比区域不能太多，否则画面杂乱（L4D 早期截图的问题）[8]。
- UI 尽量放进叙事内、做到极简：死亡空间把生命值显示在主角背部 [20][21]。

**常见美术陷阱**
- 黑位压死：换个显示器或伽马，暗部就全黑。需要亮度校准界面。
- 噪点、胶片颗粒、色差叠太多，把剪影打碎。
- 雾色太深，怪物和雾同一个明度。
- 手电光锥曝光过度：近处死白，远处死黑。

**测试片段**
1. 「黑雾对白雾」：暗走廊里，12 m 外放一只怪物，分别用黑色雾和浅灰雾，测怪物剪影和背景的亮度比（应能复现 L4D 的结论：浅雾更好读 [8]）。
2. 「伽马鲁棒性」：伽马 ±0.2、曝光三档下，地面路径是否仍可见。
3. 「光路导航」：三条岔路只有一条有光源，看测试者选哪条。

### A8 生存与制作（Survival & Crafting）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 第一人称 | 透视；vFOV 70° 左右 | 无 | 我的世界：默认 70°，范围 30–110 [22]；深海迷航（公开常识） |
| ② 第三人称 | 透视；距离 3–5 m；vFOV 55°–65° | 轨道 + 弹簧臂 | 英灵神殿 Valheim（公开常识） |
| ③ 固定斜俯视 | 透视；俯仰 40°–55° | 跟随 + 分档旋转 | 饥荒（公开常识；旋转步长**未核实**） |

**可读性规则**
- 资源节点用形状 + 颜色双重编码（矿石闪点、晶体轮廓），远处也能认出。
- 敌对生物和中立生物在剪影和配色上分开；夜里的敌对生物可以带发光眼睛（经验值）。
- 夜晚靠色温（偏蓝）表现，而不是一味压暗，资源和威胁要保持可读。
- 背包图标在 32–64 px 下可辨（经验值）。

**常见美术陷阱**
- 夜晚过暗（同恐怖类）。
- 植被过度重叠绘制 (overdraw) 加风动画，远景闪烁。
- 资源图标同色系（铜、铁、锡全是灰褐色）。
- 生物群落主色吞掉资源色（红沙漠里的红矿）。

**测试片段**
1. 「昼夜四时」：同一场景在 06/12/18/00 点，6 种资源节点分别放在 10 m 和 20 m 外，在灰度 + 夜间色彩查找表 (LUT) 下逐个辨认。
2. 「图标 32 px」：12 个图标缩到 32 px，再做色盲模拟，检查两两可分。
3. 「群落吞色」：资源色和群落主色的色相差小于 30° 时报警（经验值）。

### A9 建造与经营（Building & Management）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 自由 RTS 镜头（平移 / 旋转 / 缩放） | 透视；俯仰随缩放变化，近处 30°–45°、远处 60°–75°；距离 15–300 m；vFOV 35°–45° | 平移 + 旋转 + 缩放；俯仰、距离、FOV 走同一条曲线（避开 Nesky #16 [5]） | 城市：天际线、双点医院、过山车之星（公开常识） |
| ② 固定等轴 | 正交 / 2D；可 90° 旋转 | 边缘卷动 | 模拟城市 2000（固定等轴 [11]）；过山车大亨（公开常识） |
| ③ 正俯视信息视图 | 正交俯视 | 平移缩放 | 各类经营游戏的数据覆盖层 / 地图模式（公开常识） |

**可读性规则**
- 不同缩放级别承担不同信息，即"语义缩放"（经验值）：近景看细节和小人；中景靠屋顶剪影 + 主色认建筑类型；远景看分区色块和热力图。
- 建筑功能要能从屋顶读出来，因为俯视时大部分时间只看得到屋顶。
- 数据覆盖层用独立色板，不和基础美术撞色，并配图例。
- 人群、车辆这类小单位靠颜色和运动来读。

**常见美术陷阱**
- 屋顶全是同色同材质，看不出功能。
- 远景细节变成噪点，没做细节层级 (LOD) 简化。
- 叠上覆盖层后对比崩溃，红到绿的热力图对色盲不友好 [32]。

**测试片段**
1. 「三级缩放」：俯仰 50°，距离 20/80/250 m，8 种建筑。每一级记录能认出几种建筑。
2. 「热力图色盲」：红→绿热力图和单色相明度渐变两种方案，在色盲模拟下对比。
3. 「人群找人」：广场上 200 个小人，找出其中 1 个"任务小人"。

### A10 工厂与自动化（Factory & Automation）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 2D 俯视（伪 3D 精灵） | 正交；约 45° 观察角；滚轮缩放 | 平移 + 缩放，不旋转 | 异星工厂 Factorio：官方说几乎所有实体都按约 45° 投影 [23]。社区测量发现各实体的角度在 38°–53° 之间并不统一，有些模型为了"看起来对"做了手工调整 [24] |
| ② 第一人称 | 透视；vFOV 65°–75° | 无 | 幸福工厂 Satisfactory（公开常识） |
| ③ 纯正俯视极简 | 正交 90° | 平移 + 缩放 | shapez（公开常识） |

**可读性规则**
- 缩到最远时，传送带上的物品仍能靠颜色和形状分辨：每种物品要有独特的颜色 + 图标轮廓。
- 机器状态（运行、缺料、缺电）用图标 + 颜色 + 动画三重编码 [32]。
- 传送带、机械臂的方向箭头任何时候都要可读。
- "信息模式"是可读性的关键补丁，例如 Factorio 的 Alt 模式会在机器上叠配方图标（公开常识）。工具应支持开关这样的图标覆盖层。

**常见美术陷阱**
- 全是金属灰褐色，机器之间没有色相区分。
- 大量机器同步运动，形成动画噪声。
- 状态只靠颜色（红灯、绿灯）。
- 2D 精灵混用不同的投影角，拼接处错位。Factorio 旧铁轨只能用几乎没有透视的正俯视，和其他约 45° 的实体不一致，后来重画了 [23]。

**测试片段**
1. 「100×100 工厂」：正交俯视，可视高度 30/60/120 m，200 台机器加传送带。每一档缩放检查传送带方向和物品种类是否可读。
2. 「状态色盲」：机器状态灯在三种色盲模拟下是否可分。
3. 「投影一致性」：3D 渲染的建筑和手绘精灵放在 2:1 二等轴下，比较它们和网格的贴合程度。

### A11 生活与养成（Life Sim & Cozy）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 2D 斜俯视（正面 + 顶面） | 正交 2D；按整数倍放大像素 | 硬跟随 + 地图边界限制 | 星露谷物语：瓦片 16×16 像素 [30]（显示放大倍率**未核实**） |
| ② 固定高俯角第三人称 | 透视；俯仰 35°–50°；距离 10–15 m；vFOV 30°–40° | 软跟随；不能自由旋转 | 集合啦！动物森友会（公开常识；地平线"滚筒式"弯曲的实现方式**未核实**） |
| ③ 自由轨道 | 透视 | 轨道 + 缩放 | 模拟人生 4（公开常识） |

**可读性规则**
- 作物各生长阶段靠形状和高度区分，不只靠颜色深浅。
- 季节换色板（春夏秋冬）时，地面和可交互物之间的明度关系保持不变。
- 角色表情和情绪图标在小尺寸下可读。
- 暖色治愈系不等于低对比：保持 3–4 个明确的明度组（经验值）。

**常见美术陷阱**
- 粉彩 (pastel) 全部同一明度，画面糊成一片。
- 冬季雪地纯白，白色物品消失。
- 装饰物太多，玩家找不到能交互的东西。

**测试片段**
1. 「四季农田」：10×10 农田，4 个生长阶段 × 4 套季节 LUT，在灰度下检查各阶段是否可分。
2. 「雪地白物」：冬季场景里放白色和浅色的可拾取物。
3. 「明度组」：统计画面亮度直方图，检查有没有 3–5 个分开的峰（经验值）。

### A12 策略与战术（Strategy & Tactics）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① RTS 固定俯角 | 透视；俯仰 50°–65°；距离 25–60 m；vFOV 30°–45° | 平移 + 缩放，通常不旋转 | 星际争霸 II、帝国时代 IV（公开常识） |
| ② 回合战术网格 | 正交或窄 FOV 透视；俯仰 35°–60° | 分档旋转 + 聚焦当前单位 | 陷阵之志 Into the Breach：8×8 战场，敌人的攻击方向提前标出 [26]；幽浮 2（公开常识，旋转步长**未核实**）；火焰纹章（公开常识） |
| ③ 大战略 | 透视；拉远时切到图标化的战略视图 | 平移 + 缩放 | 全面战争、文明 VI（公开常识） |

**可读性规则**
- 阵营色是第一层级。单位再小也要能分清，并允许玩家自选阵营色 [32]。
- 兵种剪影或图标在 20–30 px 下可辨（经验值）。
- 把意图画出来：Into the Breach 直接在地图上显示敌人下一步打哪里 [26]，开发者说过会为了清晰牺牲酷点子 [27]。
- 网格线在任何地形材质上都可见，但不抢主体。
- 战争迷雾不能把阵营色洗掉。

**常见美术陷阱**
- 红绿两色当阵营色。
- 单位细节过多，远景一片模糊。
- 地形纹理噪声和单位"同频"。
- 等轴下看不出高度层（可用投影阴影 + 高度描边解决）。

**测试片段**
1. 「迷雾下的 30 对 30」：俯仰 55°、距离 40 m、vFOV 35°；两队各 30 个单位；指数雾密度取 0 / 0.02 / 0.05（经验值）。在三种色盲模拟下，统计能正确认出阵营的单位比例（目标 ≥ 95%，经验值）。
2. 「意图层」：8×8 网格上显示 5 个攻击意图箭头，检查它们和地形、单位有没有视觉冲突。
3. 「兵种剪影」：6 个兵种缩到 24 px，只看剪影能否区分。

### A13 卡牌与桌面（Card & Tabletop）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 固定俯视牌桌 | 透视；俯仰 55°–70°；距离 1–2 m（桌面尺度）；vFOV 35°–45° | 固定 | 炉石传说（公开常识） |
| ② 2D 界面主导 | 正交 2D | 固定 | 杀戮尖塔、小丑牌 Balatro（公开常识） |
| ③ 第一人称坐在桌前 | 透视；俯仰 30°–50°；距离 0.8–1.5 m | 头部小范围转动 | 邪恶冥刻 Inscryption、恶魔轮盘 Buckshot Roulette（公开常识） |

**可读性规则**
- 卡面信息分层：费用、攻击、生命放在固定位置，数字配高对比底板；卡图排在第二层。
- 牌桌降饱和、降对比，卡牌边框提亮。
- 稀有度用边框或宝石形状 + 颜色表示。
- 悬停放大 (hover zoom)，小尺寸的文字不能是唯一信息源。

**常见美术陷阱**
- 华丽卡框挤占规则文字的空间。
- 卡图缩小后变成色块。
- CRT、颗粒、扭曲后处理让小字难读。做 Balatro 式 CRT 效果要提供开关（Balatro 本身是否可关**未核实**）。

**测试片段**
1. 「120 px 卡牌」：卡高 120 px 时规则文字是否可读；模糊测试下费用数字是否还能认出。
2. 「稀有度色盲」：4 档稀有度边框在色盲模拟下比较。
3. 「牌桌分离」：测卡牌和牌桌的亮度比。

### A14 竞速与驾驶（Racing & Driving）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 追尾镜头 (chase cam) | 透视；车后 5–7 m、高 1.5–2.5 m（俯仰约 8°–15°）；vFOV 55°–65°，随速度加 5°–15° | 弹簧阻尼跟随；偏航稍滞后于车头，好看到漂移角 | 马力欧卡丁车 8、极限竞速：地平线（公开常识） |
| ② 引擎盖 / 保险杠 / 座舱 | 透视；vFOV 50°–60° | 刚性挂在车上，加轻微晃动 | GT 赛车、极限竞速（公开常识） |
| ③ 高空斜俯视 | 透视；俯仰 35°–60° | 跟随 + 前瞻 | art of rally、微型机器 Micro Machines（公开常识） |

Nesky 把"FOV 变化太快"和"震屏过度"都列为错误 [5]，速度感特效要设上限。

**可读性规则**
- 路面和路肩的明度差要大，灰度下赛道边界一目了然。
- 弯道提示（路牌、减速标记）在 100 m 外可读。
- 对手车辆在明度上和赛道、天空分开；暗环境里靠尾灯。
- 速度感来自运动模糊、速度线和 FOV，但不能淹没赛道边界。

**常见美术陷阱**
- 运动模糊 + 速度线 + FOV 冲刺叠在一起，引起晕动。
- 路面和草地同一明度。
- 逆光时天空泛光、镜头光晕把前方赛道洗白。

**测试片段**
1. 「200 km/h 边界」：样条赛道 + 追尾镜头，在前方 50 m 和 100 m 处采样路面和路肩的亮度比（目标 ≥ 2:1，经验值）。
2. 「FOV 冲刺上限」：3 秒内从 0 加速到极速，FOV 变化率 ≤ 10°/s（经验值）。
3. 「逆光」：太阳低角度在正前方时，测赛道边界。

### A15 沙盒与物理（Sandbox & Physics）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 第一人称 | 透视；vFOV 70°–75° | 无 | 我的世界 [22]、拆迁 Teardown、盖瑞模组（公开常识） |
| ② 建造轨道 / 自由飞行 | 透视；绕作品中心旋转，可平移；vFOV 45°–60° | 轨道 / 飞行 | 围攻 Besiege、坎巴拉太空计划的装配大楼（公开常识） |
| ③ 第三人称 | 透视；距离 3–6 m | 轨道 + 弹簧臂 | 人类一败涂地（公开常识） |

**可读性规则**
- 材质的外观和物理行为一一对应（木头会烧、金属不会），颜色和纹理要稳定地映射到材质类别。
- 能抓、能交互的物体要有视觉暗示 (affordance)。
- 破坏后的碎片降低对比、尽快淡出，不要淹没玩家角色。
- 提供尺度线索：门、人这类已知大小的物体（Nesky：距离难判断是错误之一 [5]）。

**常见美术陷阱**
- 体素或方块的调色板单一，材质分不出来。
- 碎片和粒子停留太久，画面全是噪声。
- 正交视角下没有尺度线索。

**测试片段**
1. 「200 碎片」：爆炸后留下 200 个碎片，在灰度下 1 秒内能否找到玩家角色。
2. 「材质辨识」：6 种物理材质的方块并排，在三种光照下辨认。
3. 「尺度」：同一物体放大 2 倍，分别在有参照物和无参照物时对比。

### A16 叙事与视觉小说（Narrative & Visual Novel）

| 方案 | 投影 / 俯仰 / 距离 / FOV | 跟随行为 | 代表作 |
|---|---|---|---|
| ① 2D 立绘 + 背景 (ADV) | 正交 2D；镜头只做推拉和震动 | 无 | 逆转裁判、命运石之门、心跳文学部（公开常识） |
| ② 电影化正反打 (shot-reverse-shot) | 透视；vFOV 25°–40°（约等于全画幅 33–55 mm 镜头，作者换算） | 预设机位；遵守 180° 轴线规则（Nesky #20 [5]） | 行尸走肉 (Telltale)、奇异人生（公开常识） |
| ③ 等轴 / 舞台式 | 正交或窄 FOV 透视 | 跟随或固定 | 极乐迪斯科、肯塔基零号公路（公开常识） |

**可读性规则**
- 文本框放在任何 CG 背景上都要达到 4.5:1 [34]，靠半透明底板 (scrim) 或渐变遮罩。
- 说话人用名牌颜色 + 位置 + 立绘高亮来区分，非说话者压暗。
- 背景轻微模糊、降饱和，把立绘和背景分开。
- 选项的已选、未选、锁定状态不能只靠颜色表示 [32]。

**常见美术陷阱**
- 文字压在高频背景上。
- 中文字体字重不够或字号太小。WCAG 对 CJK"大字"的标准是按等效字号算的 [34]。
- 转场和 UI 动画过多（Persona 5 早期的教训 [47]）。

**测试片段**
1. 「五背景文本框」：亮天空、夜景、繁华街道、纯白、纯黑 5 张背景，自动计算文本对比度。
2. 「说话人」：3 个角色同屏，非说话者压暗 30%（经验值），在灰度下辨认谁在说话。
3. 「正反打越轴」：两人对话时切换镜头，自动检查是否越过 180° 轴线。

## B. UI 风格目录（26 种）

> 每种风格依次写：定义、CSS 特征（边框 / 圆角 / 阴影 / 背景 / 字体 / 色彩 / 图标 / 动效）、小段 CSS、代表游戏、适用场景（HUD / 菜单 / 对话）、陷阱。字体只列可免费商用或开源的家族，中文字体另行标出。CSS 数值都是经验值，用来复现风格的"手感"，不是任何游戏的实际取值。
>
> 中文网页字体普遍很大（单个字重常有数 MB），要做子集化或按 unicode-range 分片加载，这对所有风格都适用。

### B1 新粗野主义（Neo-Brutalism）
- **定义**：从粗野主义网页设计演化而来，特点是高对比、方块布局、大胆用色、粗边框和"不精致"的元素，比原始粗野主义更多彩、更有秩序 [36]。
- **CSS 特征**：边框 2–4 px 纯黑实线；圆角 0–8 px；**硬阴影**，即单色、不模糊、偏移几像素 [36]；背景是纯色块（黄、粉、薄荷绿）；标题用怪异或粗黑字体，正文用中性无衬线 [36]；图标是粗线条单色；动效是按下时元素位移到阴影位置、阴影归零。
```css
.nb { --ink:#111; background:#FFE066; color:var(--ink);
  border:3px solid var(--ink); border-radius:4px; box-shadow:6px 6px 0 var(--ink);
  font:800 16px/1.2 "Space Grotesk","Archivo Black","Noto Sans SC",sans-serif; }
.nb:active { transform:translate(6px,6px); box-shadow:0 0 0 var(--ink); }
```
- **代表游戏**：游戏里成体系使用的例子少，多见于网站和工具界面；独立游戏的商店页、菜单有采用，但具体作品**未核实**。
- **适用**：菜单、商店、工具类面板 ✓；HUD △（粗边框会占屏）；对话 △。
- **陷阱**：亮色组合（例如黄配青）可能对比度不达标；粗形体堆太多，画面喧闹、层级扁平；按钮的可点击感会变弱。建议主色限制在 2–3 个，交互状态用下划线或颜色变化表示 [36]。

### B2 玻璃拟态（Glassmorphism）
- **定义**：用不同程度的半透明模拟磨砂玻璃，靠它区分前景和背景，常叠在渐变或复杂背景上；效果主要来自不透明度和背景模糊，描边和渐变负责增加立体感 [35]。
- **CSS 特征**：`background: rgb(255 255 255 / .1–.25)`；`backdrop-filter: blur(12–24px) saturate(140%)`；1 px 半透明白描边；圆角 12–20 px；大而柔的投影；字体用细到中等字重的无衬线（Inter、思源黑体）；动效是淡入加轻微缩放。
```css
.glass { background:rgb(255 255 255 / .14); backdrop-filter:blur(16px) saturate(140%);
  border:1px solid rgb(255 255 255 / .35); border-radius:16px;
  box-shadow:0 8px 32px rgb(0 0 0 / .25); color:#fff; }
```
- **代表游戏**：游戏里的系统菜单、暂停菜单偶有使用，具体作品**未核实**；成体系的参照主要是操作系统 UI（Windows Aero、Apple 的半透明材质）。
- **适用**：暂停菜单、设置面板 ✓；HUD △（背景每帧都在变）；对话 △。
- **陷阱**：①对比度：文字下方的背景颜色不断变化，可读性不稳定；NN/g 建议背景越花模糊越重，并给玩家"降低透明度 / 提高对比"的选项 [35]。②性能：`backdrop-filter` 必须有半透明背景才看得到效果，父元素 `opacity < 1` 会截断它的作用范围（backdrop root）；2024 年进入 Baseline，旧设备可能不支持 [38]。叠在**每帧都在动的 WebGL 画布**上时，浏览器每帧都要重新模糊下面的内容，大面积、大半径时开销明显（经验判断，MDN 没给性能数据，**未核实**）。可以改成在 WebGL 里做一次降采样模糊（例如 Kawase 模糊），再把结果当面板背景。

### B3 新拟态（Neumorphism / Soft UI）
- **定义**：元素和背景同色，用一对方向相反的明暗阴影做出"浮起"或"压入"的软塑料效果 [39]。
- **CSS 特征**：背景和父元素同色（常见 `#E0E5EC`）；两层 `box-shadow`：右下暗影、左上亮影；按下时改成 `inset`；圆角 12–24 px，是这一风格的标志；可加和光源方向一致的细微渐变 [39]；字体用低对比灰；图标线性、灰色。
```css
.neu { --bg:#E0E5EC; background:var(--bg); border-radius:20px;
  box-shadow:9px 9px 16px #a3b1c6, -9px -9px 16px #fff; }
.neu:active { box-shadow:inset 6px 6px 10px #a3b1c6, inset -6px -6px 10px #fff; }
```
- **代表游戏**：几乎没有游戏把它当主风格；偶见于休闲手游的设置页，具体作品**未核实**。
- **适用**：静态卡片、设置面板 △；HUD ✗；对话 ✗。
- **陷阱**：阴影带来的对比很弱，对比检查工具通常忽略阴影；低视力和色觉障碍玩家看不清边界；按钮看起来像静态内容；悬停、焦点、错误、禁用状态很难表达；背景接近纯白或纯黑时阴影失效 [39]。建议只用在静态卡片上。

### B4 扁平 / 材料设计（Flat / Material）
- **定义**：扁平设计去掉光泽和立体效果，是对拟物风的反动；微软 Metro 风格和 Windows 8 把它推向主流。"扁平 2.0"保留少量阴影和层次，用来找回可点击的暗示，Google 的 Material Design 就属于这一类 [37]。
- **CSS 特征**：纯色填充；无边框或 1 px 浅灰描边；圆角 4–12 px（Material 3 偏大圆角）；只用 1–2 层很浅的投影表示层级；字体用 Roboto、Inter、思源黑体，字重 400/500；图标是 24 px 网格的线性或填充图标；动效是 150–300 ms 的缓动。
```css
.flat { background:#fff; border-radius:12px; color:#1d1b20;
  box-shadow:0 1px 2px rgb(0 0 0 / .3), 0 1px 3px 1px rgb(0 0 0 / .15);
  font:500 14px/20px Roboto,"Noto Sans SC",sans-serif; letter-spacing:.1px; }
```
- **代表游戏**：迷你地铁 Mini Metro、阿尔托的冒险 Alto's Adventure、Threes!（公开常识，均为扁平图形 + 极简 UI）。
- **适用**：HUD ✓（干净、开销低）；菜单 ✓；对话 ✓。
- **陷阱**：可点击的暗示（signifier）丢失，玩家分不清什么能点。NN/g 提醒不要为了追潮流牺牲可用性 [37]。另外放进奇幻或写实游戏里会显得"像 App"。

### B5 拟物（Skeuomorphic）
- **定义**：模仿真实物体的材质和结构（皮革、木头、金属、纸张、按钮的物理凸起），借现实隐喻来提示用法 [37]。
- **CSS 特征**：用 `border-image` 九宫格边框（木框、金属框）；纹理背景图；多层 `inset` 高光和暗边模拟倒角；圆角跟随材质；字体用衬线或刻印风；图标是写实小物件；动效有物理感（弹簧、翻页、开盒）。
```css
.skeu { background:url(wood.jpg) center/cover, linear-gradient(#8b5a2b,#5e3b1a);
  border:12px solid transparent; border-image:url(frame.png) 24 round;
  box-shadow:inset 0 1px 0 rgb(255 255 255 / .35), inset 0 -2px 0 rgb(0 0 0 / .4), 0 3px 6px rgb(0 0 0 / .5); }
```
- **代表游戏**：炉石传说（实体卡盒、牌桌和开包都做成物理感，公开常识）；请出示证件（桌面上的证件实物）；未上锁的房间 The Room（公开常识）。
- **适用**：菜单、物品栏、谜题界面 ✓；HUD △（容易厚重）；对话 ✓（书信、便签）。
- **陷阱**：贴图多、包体大；高分辨率屏需要 2x/3x 素材；风格必须和世界观统一，否则显得廉价；纹理下的文字要单独加底。

### B6 像素 UI（Pixel UI）
- **定义**：低分辨率像素画的边框、字体和图标，按整数倍放大显示。
- **CSS 特征**：用 `border-image` 九宫格加 `image-rendering: pixelated`；不用圆角，阶梯形转角用 `clip-path` 或像素图实现；阴影是 1 个像素单位的硬偏移；字体用 Press Start 2P、VT323，中文用 Zpix（最像素）、Fusion Pixel（缝合像素）；色板限定 4–32 色；动效是逐帧、无缓动，光标闪烁。
```css
.px { image-rendering:pixelated; border:16px solid transparent; border-image:url(px-frame.png) 8 fill / 16px stretch;
  font:16px/1 "Zpix","Press Start 2P",monospace; color:#f4f4f4; text-shadow:2px 2px 0 #000; }
```
- **代表游戏**：星露谷物语、蔚蓝 Celeste、传说之下 Undertale（公开常识）。
- **适用**：HUD ✓；菜单 ✓；对话 ✓。
- **陷阱**：非整数缩放会让像素不均匀，要锁定整数倍；像素中文字体在 12 px 下笔画容易粘连；高 DPI 屏上像素字体太小；像素 UI 和高清 3D 混用时，要统一"像素密度"（同屏像素尺寸一致）。

### B7 手绘笔记本 / 草图（Hand-drawn Notebook / Sketch）
- **定义**：像写在横线纸、方格纸上的笔迹、涂鸦和便签，线条不规则。
- **CSS 特征**：背景用 `repeating-linear-gradient` 画横线或方格；边框用不对称的大圆角制造"手画"抖动（常见写法 `255px 15px 225px 15px / 15px 225px 15px 255px`）；SVG `feTurbulence + feDisplacementMap` 给线条加抖动；字体用 Caveat、Patrick Hand，中文用站酷快乐体、霞鹜文楷；动效是笔画描出 (`stroke-dashoffset`) 和便签轻微旋转。
```css
.note { background:repeating-linear-gradient(#fffef8 0 27px,#c9e0f5 27px 28px);
  border:2px solid #333; border-radius:255px 15px 225px 15px/15px 225px 15px 255px;
  font:20px/28px "Caveat","ZCOOL KuaiLe",cursive; transform:rotate(-.6deg); }
```
- **代表游戏**：奥伯拉丁的回归：玩家拿到的航海日志里有船员画像、名册和船体图，是解谜的核心界面 [29]；涂鸦跳跃 Doodle Jump（方格纸背景）、蜡笔物理学 Crayon Physics Deluxe（公开常识）。
- **适用**：菜单、日志、地图 ✓；对话 ✓；HUD △（手写字体在小字号下难读）。
- **陷阱**：手写字体做正文，可读性差；中文手写字体字符集常常不全，生僻字会回退到别的字体；`feDisplacementMap` 用在大面积上有性能开销。

### B8 中式卷轴 / 印章 / 宣纸 / 书法（Chinese Scroll & Seal）
- **定义**：宣纸底、水墨笔触、书法标题、朱红印章、卷轴装裱，常配竖排文字。
- **CSS 特征**：宣纸纹理（米黄 `#F2E8CF` + 噪点）；墨色 `#1C1C1C`；朱砂红 `#B22C2C` 作强调色；卷轴上下轴用伪元素画木轴渐变；印章是方形红底白字（阴文）或红字（阳文），用 SVG 滤镜做斑驳边缘；竖排 `writing-mode: vertical-rl`；标题用马善政毛笔楷书 (Ma Shan Zheng)，正文用思源宋体或霞鹜文楷；图标用水墨点染；动效是卷轴展开（`clip-path: inset()` 动画）和墨迹晕开（mask 渐变）。
```css
.scroll { background:#F2E8CF url(xuan-noise.png); color:#1C1C1C; writing-mode:vertical-rl;
  font:18px/2 "Noto Serif SC","LXGW WenKai",serif; letter-spacing:.2em; padding:2em 1.5em; }
.seal { display:inline-block; background:#B22C2C; color:#fff; border-radius:3px;
  font:20px/1 "Ma Shan Zheng",serif; padding:4px; filter:url(#rough-edge); }
```
- **代表游戏**：太吾绘卷（标题即"绘卷"；UI 的具体纸本元素**未核实**）；绘真·妙笔千山（青绿山水画风，公开常识）；黑神话：悟空（书法标题，UI 细节**未核实**）。日式水墨见 B25。
- **适用**：菜单、图鉴、章节标题 ✓；对话 ✓（横排正文 + 竖排标题）；HUD △（竖排、书法字体不适合快速读数）。
- **陷阱**：书法字体只适合大标题，用在正文或数字上会不可读；宣纸底和墨色字之间要留足明度差；红色印章别和"危险 / 敌方红"混用；竖排在网页里的数字、英文混排要处理 `text-combine-upright`。

### B9 科幻 HUD / 叙事内 UI（Sci-fi HUD / Diegetic UI）
- **定义**：屏幕全息、头盔目镜式的线框 UI。叙事内 (diegetic) UI 把信息放进游戏世界本身，例如死亡空间里所有界面都是游戏内的全息投影，生命值显示在主角背部 [20]。HUD 一词借自飞机的平视显示器，叙事内 UI 能帮助维持代入感 [21]。
- **CSS 特征**：1 px 细线框；切角 (`clip-path` 多边形)；四角括号装饰；单色青 `#7FF6FF` 或琥珀色；半透明深色底；全大写 + 字距 0.1–0.2em；字体用 Rajdhani、Orbitron、Share Tech Mono；`text-shadow` 发光；动效有开机扫描、闪烁、数字滚动。
```css
.hud { --c:#7FF6FF; color:var(--c); border:1px solid var(--c); background:rgb(0 30 40 / .35);
  clip-path:polygon(12px 0,100% 0,100% calc(100% - 12px),calc(100% - 12px) 100%,0 100%,0 12px);
  font:600 14px/1.4 "Rajdhani","Share Tech Mono",monospace; text-transform:uppercase;
  letter-spacing:.15em; text-shadow:0 0 6px var(--c); }
```
- **代表游戏**：死亡空间（叙事内 UI [20][21]）；银河战士 Prime（头盔面罩 HUD）、光环 Halo（公开常识）。
- **适用**：HUD ✓；菜单 ✓；对话 △（大段文字不适合细体大写）。
- **陷阱**：细线 + 发光叠在亮背景上会消失（对比随世界变化）；全大写 + 宽字距让中文版排不下；发光、扫描线动画如果用 CSS filter 实现会有开销；叙事内 UI 放在 3D 空间时，要测远距离和斜角的可读性。

### B10 JRPG 窗口（JRPG Window）
- **定义**：经典日式 RPG 的对话框和菜单框。最终幻想式是蓝色渐变底 + 白色圆角边框；勇者斗恶龙式是黑底 + 白色双线圆角框。
- **CSS 特征**：边框 2–4 px 白色，外加 1 px 黑色描边；圆角 6–10 px；最终幻想式的背景是垂直蓝色渐变（`#3050C8 → #101860`）；文字白色 + 1 px 黑投影；像素字体或圆体；光标是手指（FF）或三角（DQ）；文字以打字机效果逐字出现。
```css
.ff { background:linear-gradient(#3050c8,#101860); color:#fff; text-shadow:1px 1px 0 #000;
  border:3px solid #e8e8f8; border-radius:8px; box-shadow:0 0 0 1px #000, inset 0 0 0 1px #000; }
.dq { background:#000; color:#fff; border:4px double #fff; border-radius:10px; }
```
- **代表游戏**：最终幻想（窗口颜色可在设置里调，公开常识）、勇者斗恶龙系列、地球冒险 EarthBound（窗口花纹可选，公开常识）；歧路旅人 Octopath Traveler 是现代变体。
- **适用**：对话 ✓；菜单 ✓；HUD ✓（战斗状态框）。
- **陷阱**：纯蓝底配白字对比没问题，但蓝底叠在蓝天场景上会混在一起；窗口太多层层嵌套时层级不清；逐字显示要提供"立即显示全部"。

### B11 羊皮纸 / 奇幻（Parchment / Fantasy）
- **定义**：做旧羊皮纸、墨水手稿、烫金边、蜡封，常见于西幻 RPG。
- **CSS 特征**：羊皮纸纹理 + 边缘焦黄（`radial-gradient` 暗角）；毛边用 `mask-image` 或九宫格图；描边用棕墨 `#3B2A1A`；金色饰角；字体用 Cinzel（标题）、IM Fell English（正文），中文用思源宋体；首字母放大 (drop cap)；动效是纸张展开、墨迹淡入。
```css
.parch { background:#EAD9B0 url(parchment.jpg) center/cover; color:#3B2A1A;
  box-shadow:inset 0 0 60px rgb(90 50 10 / .45); border-radius:2px;
  font:17px/1.6 "IM Fell English","Noto Serif SC",serif; }
.parch h2 { font:700 22px "Cinzel",serif; letter-spacing:.08em; }
```
- **代表游戏**：上古卷轴 IV：湮没（羊皮纸菜单，公开常识）、天国：拯救、博德之门 (1998)（公开常识）。
- **适用**：菜单、任务日志、地图 ✓；对话 ✓；HUD △（纹理底太重）。
- **陷阱**：棕墨配米黄底的对比常常只有 4:1 左右，要实测；纹理不均导致局部对比不足；古风英文字体做正文难读。

### B12 漫画 / 漫画分格（Comic / Manga Panel）
- **定义**：粗黑分格框、对白气泡、网点 (halftone)、拟声字和速度线。
- **CSS 特征**：边框 3–5 px 纯黑；分格可以倾斜（`clip-path` 多边形或 `skew`）；网点用 `radial-gradient` + `background-size: 6px 6px`；气泡尾巴用伪元素；字体用 Bangers、Comic Neue，中文用站酷快乐体；动效是分格滑入、冲击帧（缩放 + 抖动）。
```css
.panel { border:4px solid #000; background:#fff;
  clip-path:polygon(0 0,100% 4%,98% 100%,2% 96%); }
.halftone { background:radial-gradient(#000 22%,transparent 23%) 0 0/6px 6px, #FFD84D; }
.bubble { background:#fff; border:3px solid #000; border-radius:50%/40%; font:700 18px "Bangers","ZCOOL KuaiLe"; }
```
- **代表游戏**：Comix Zone、XIII (2003)、红侠乔伊 Viewtiful Joe（公开常识）。
- **适用**：对话、过场 ✓；菜单 ✓；HUD △（分格太占屏）。
- **陷阱**：网点和速度线会和文字抢对比；倾斜分格会把正文挤进边角；拟声字太多，信息层级就乱了。

### B13 CRT 终端（CRT Terminal）
- **定义**：老式阴极射线管显示器上的绿色或琥珀色荧光字终端。
- **CSS 特征**：近黑底；荧光绿 `#33FF66` 或琥珀 `#FFB000` 单色；等宽字体 VT323、IBM Plex Mono；`text-shadow` 辉光；扫描线用 `repeating-linear-gradient` 叠层；屏幕弯曲和色散最好在 WebGL 着色器里做；动效有光标闪烁、逐字打印、开机闪烁。
```css
.crt { background:#020a02; color:#33ff66; font:20px/1.3 "VT323","IBM Plex Mono",monospace;
  text-shadow:0 0 4px rgb(51 255 102 / .7); position:relative; }
.crt::after { content:""; position:absolute; inset:0; pointer-events:none;
  background:repeating-linear-gradient(transparent 0 2px, rgb(0 0 0 / .25) 2px 3px); }
```
- **代表游戏**：辐射 3/4 的终端机（公开常识）、异形：隔离（复古未来电脑，公开常识）、Hacknet（公开常识）。
- **适用**：游戏内电脑、黑客小游戏、菜单 ✓；HUD △；对话 ✓（终端聊天）。
- **陷阱**：单色界面没法用颜色区分状态，必须靠符号和反显；辉光和扫描线降低小字可读性，要能关；闪烁动画要注意光敏癫痫风险，频率和幅度都要克制。

### B14 Y2K 铬金属（Y2K Chrome）
- **定义**：1990 年代末到 2000 年代初的未来感：铬金属、彩色半透明塑料、圆润的"blobject"造型，亮色有青柠、橙、亮粉 [41]。
- **CSS 特征**：多段银色线性渐变模拟铬；胶囊形圆角（`999px`）；`inset` 高光 + 底部暗边；半透明彩色塑料（低不透明度的彩色背景）；粗圆体或宽体无衬线；动效有高光扫过 (shine sweep) 和果冻弹跳。
```css
.chrome { background:linear-gradient(180deg,#fdfdfd 0%,#c9ced6 45%,#8a929e 50%,#e6e9ee 100%);
  border-radius:999px; color:#1a1a1a; font:800 15px "Fredoka","Noto Sans SC",sans-serif;
  box-shadow:inset 0 2px 1px #fff, inset 0 -3px 4px rgb(0 0 0 / .35), 0 4px 10px rgb(0 0 0 / .4); }
```
- **代表游戏**：反重力赛车 Wipeout 系列：视觉、包装和说明书由设计工作室 The Designers Republic 负责，风格是日本动漫图像加颠覆的企业标志，"最大化的极简" [42]；街头涂鸦 Jet Set Radio (2000)、炸弹冲刺 Bomb Rush Cyberfunk（Y2K 复兴，公开常识）。
- **适用**：菜单、标题画面 ✓；HUD △；对话 △。
- **陷阱**：铬渐变上叠文字，对比会随渐变段变化；高光太多显得廉价；渐变层多了要注意绘制开销。

### B15 瑞士 / 国际主义网格（Swiss / International Typographic Style）
- **定义**：追求清晰和客观：网格结构、非对称布局、无衬线字体（Akzidenz-Grotesk、Helvetica、Univers）、左对齐右侧参差、用摄影而不是插画 [43]。
- **CSS 特征**：CSS Grid 12 栏；无边框或细分隔线；不用圆角和阴影；黑白灰 + 一个强调色（常用红）；字号对比极大（标题和正文可差 4 倍以上）；字体用 Inter、Helvetica Neue，中文用思源黑体；图标极少；动效是硬切或简短的位移。
```css
.swiss { display:grid; grid-template-columns:repeat(12,1fr); gap:16px;
  font-family:"Inter","Helvetica Neue","Noto Sans SC",sans-serif; color:#111; background:#fafafa; }
.swiss h1 { grid-column:1 / span 8; font:700 64px/0.95 inherit; letter-spacing:-.02em; }
.swiss .accent { color:#E30613; }
```
- **代表游戏**：迷你地铁 Mini Metro（地铁线路图式极简，公开常识）、Wipeout（tDR 的平面设计 [42]）、镜之边缘（极简界面，公开常识）。
- **适用**：菜单、数据界面、HUD ✓。
- **陷阱**：太"冷"，不适合温情题材；没有装饰时只能靠排版建立层级，对设计功底要求高。

### B16 构成主义（Constructivism）
- **定义**：苏联先锋派的平面设计：鲜艳色彩、几何形状、粗体字、带情绪冲击的字效，以及照片拼贴 (photomontage) [45]。
- **CSS 特征**：红、黑、米白三色（这是设计史上的常见归纳，维基页面没有直接说明 [45]）；对角线构图（元素旋转 15°–30°）；楔形、圆、条带等几何块；粗压缩无衬线（Oswald、Bebas Neue，中文用思源黑体 Heavy）；照片做成单色或网点；动效是斜向冲入。
```css
.constr { background:#F1E9D2; color:#111; font:700 28px/1 "Bebas Neue","Noto Sans SC",sans-serif; }
.constr .wedge { background:#C8102E; clip-path:polygon(0 0,100% 50%,0 100%); transform:rotate(-18deg); }
```
- **代表游戏**：请出示证件 Papers, Please（虚构东欧国家的宣传海报美学，公开常识）；命令与征服：红色警戒 3 的苏联阵营界面（**未核实**）。
- **适用**：菜单、宣传画、标题 ✓；HUD △（斜排不利于快速读数）。
- **陷阱**：大面积红黑容易给人压迫感；和政治符号关联强，要注意题材语境；斜排文字难读。

### B17 装饰艺术（Art Deco）
- **定义**：1920–30 年代的装饰风格：对称的几何纹样（放射、阶梯、V 形）、金黑配色、细双线边框。
- **CSS 特征**：深色底（黑、海军蓝）+ 金色 `#C9A54C` 细线；双线边框（`border: 3px double`）；放射纹（`repeating-conic-gradient`）；对称构图；几何展示字体 Poiret One、Limelight，全大写 + 宽字距；动效是对称展开、金线描出。
```css
.deco { background:#0E1525; color:#E9D8A6; border:3px double #C9A54C; padding:24px;
  font:400 18px "Poiret One","Noto Serif SC",serif; letter-spacing:.2em; text-transform:uppercase;
  background-image:repeating-conic-gradient(from 0deg at 50% 0%, rgb(201 165 76 / .08) 0 6deg, transparent 6deg 12deg); }
```
- **代表游戏**：生化奇兵 BioShock：Rapture 的环境大量取材装饰艺术，团队认为它简洁的大形体很适合做环境 [46]（维基没有提到界面，UI 的具体取材**未核实**）；冥界狂想曲 Grim Fandango（装饰艺术 + 亡灵节，公开常识）。
- **适用**：菜单、标题、物品卡 ✓；HUD △；对话 ✓。
- **陷阱**：细金线在低分辨率下发虚；宽字距全大写的中文版要另行设计；装饰纹太多会压过信息。

### B18 Persona 式拼贴（Persona-style Collage）
- **定义**：Persona 5 的 UI 以红色为主色，刻意营造"刺眼"的感觉；字体颜色反复测试后定为黑白，除了 HP/SP 条外整个界面只用红、黑、白三色 [47]。另一大特征是勒索信式拼贴字和锯齿多边形。
- **CSS 特征**：红 `#E60012`、黑、白三色；`clip-path` 锯齿多边形；元素整体旋转 −8°～8°；勒索信式字体（每个字母不同字体、底色、旋转）；高对比黑白描边；动效是快速硬切、抖动、二次弹出。
```css
.p5 { background:#E60012; color:#000; clip-path:polygon(2% 8%,100% 0,96% 92%,0 100%);
  transform:rotate(-4deg); font:900 28px "Anton","Noto Sans SC",sans-serif; }
.p5 .ransom span:nth-child(odd) { background:#000; color:#fff; transform:rotate(3deg); display:inline-block; }
```
- **代表游戏**：女神异闻录 5 / 5 皇家版 [47]、女神异闻录 5 战略版（公开常识）。
- **适用**：菜单、战斗指令、结算 ✓；HUD ✓；对话 ✓（风格化对话框）。
- **陷阱**：Persona 5 早期 UI 动画多到遮挡了画面，后来减少动画并调整文字方向来平衡可用性和风格 [47]；倾斜加混排字体，很难做本地化；整屏高饱和红容易疲劳。

### B19 孟菲斯（Memphis）
- **定义**：1980 年代意大利孟菲斯设计团体的风格：鲜艳饱和色、抽象装饰、不对称造型、几何实体与镂空、塑料层压板和水磨石纹 [44]；评论者形容它是"包豪斯和费雪玩具的仓促联姻" [44]。
- **CSS 特征**：糖果色（粉、黄、青、紫）；黑色粗描边；波浪线、三角、圆点、碎屑纹（`radial-gradient` + SVG pattern）；元素随机旋转；圆润的粗体；动效是弹跳和贴纸贴上的效果。
```css
.memphis { background:#FFF4E0; border:3px solid #111; border-radius:8px; box-shadow:5px 5px 0 #FF5DA2;
  background-image:radial-gradient(#111 1.5px,transparent 2px), radial-gradient(#27C3F0 2px,transparent 2.5px);
  background-size:22px 22px, 37px 37px; font:800 18px "Fredoka","ZCOOL KuaiLe",sans-serif; }
```
- **代表游戏**：游戏里明确以孟菲斯为母题的作品，本次没找到可靠来源；喷射战士 Splatoon 等作品的波点、贴纸式 UI 有相近元素（主观判断，**未核实**）。
- **适用**：休闲、派对游戏的菜单 ✓；HUD △；对话 △。
- **陷阱**：背景纹样会和文字抢对比，文字下面要垫纯色块；风格容易显得过时或幼稚。

### B20 极简单色（Minimal Monochrome）
- **定义**：灰阶 + 至多一个强调色，大量留白，信息降到最少，甚至不要 HUD。
- **CSS 特征**：无边框或 1 px 细线；无阴影；细体或常规体的几何无衬线；图标纯线性；动效是缓慢淡入淡出。
```css
.mono { --fg:#EDEDED; --bg:#0B0B0B; --accent:#E8C547; color:var(--fg); background:transparent;
  font:300 15px/1.6 "Inter","Noto Sans SC",sans-serif; letter-spacing:.04em; }
.mono .rule { border-top:1px solid rgb(237 237 237 / .25); }
```
- **代表游戏**：地狱边境 Limbo、Inside、迷你地铁（公开常识）。Ico 完全没有 HUD，靠环境和声音提示 [21]。
- **适用**：HUD ✓；菜单 ✓；对话 ✓。
- **陷阱**：可点击暗示丢失（同扁平设计 [37]）；细体小字在亮场景上看不清；只有一个强调色时，危险和收益区分不开，必须用形状补足。

### B21 Frutiger Aero
- **定义**：约 2004–2013 年盛行：鲜艳色彩、3D 图形、光泽质感、拟物；常见蓝天、草地、水、气泡、极光、镜头光晕和散景；主色是亮黄、蓝、绿 [40]。
- **CSS 特征**：高光玻璃按钮（上半部白色渐变高光）；天蓝到草绿的渐变；圆角 12–20 px；柔和外发光；字体用 Frutiger、Segoe UI 类的人文无衬线（免费替代：Nunito Sans、思源黑体）；图标是光泽 3D；动效是气泡上浮、柔和缩放。
```css
.aero { background:linear-gradient(#7fd3ff,#1f8fe0); border-radius:14px; color:#fff;
  border:1px solid rgb(255 255 255 / .6); box-shadow:0 4px 14px rgb(0 80 160 / .35);
  position:relative; overflow:hidden; font:600 16px "Nunito Sans","Noto Sans SC",sans-serif; }
.aero::before { content:""; position:absolute; inset:0 0 50% 0; border-radius:14px 14px 40% 40%;
  background:linear-gradient(rgb(255 255 255 / .75), rgb(255 255 255 / .1)); }
```
- **代表游戏**：Wii 主机与 Wii Sports (2006)、模拟人生 3、水果忍者（维基列为该风格的例子 [40]）。
- **适用**：菜单 ✓；HUD ✓（休闲）；对话 ✓。
- **陷阱**：白字叠在浅蓝高光上对比不足；光泽层多，绘制开销比扁平风高；风格时代感很强。

### B22 蒸汽波 / 合成波（Vaporwave / Synthwave）
- **定义**：合成波是 80 年代霓虹复古未来（日落条纹、透视网格地平线、紫粉青）；蒸汽波更偏 90 年代网络和消费文化的讽刺拼贴（Windows 95 窗口、希腊石膏像、片假名）。
- **CSS 特征**：粉 `#FF71CE`、青 `#01CDFE`、紫 `#B967FF` 渐变；霓虹 `text-shadow` 多层；透视网格（CSS 3D `perspective` + `repeating-linear-gradient`）；蒸汽波常用 Windows 95 式的灰色斜面窗口；字体用合成波的铬金属斜体（Monoton 等）或蒸汽波的全角拉丁字母；动效是网格滚动、VHS 抖动。
```css
.synth { background:linear-gradient(#2b1055 0%,#7597de 100%); color:#fff;
  text-shadow:0 0 4px #fff, 0 0 12px #FF71CE, 0 0 24px #FF71CE; font:400 32px "Monoton",sans-serif; }
.win95 { background:#C0C0C0; border:2px solid; border-color:#fff #404040 #404040 #fff; font:12px "MS Sans Serif",Tahoma,sans-serif; }
```
- **代表游戏**：孤岛惊魂 3：血龙、迈阿密热线（合成波霓虹，公开常识）；纯蒸汽波的游戏 UI 例子**未核实**。
- **适用**：标题、菜单 ✓；HUD △；对话 △。
- **陷阱**：多层霓虹 `text-shadow` 在大量文字上很耗性能；粉配青对色觉障碍者不友好；风格噱头大于功能，长时间游玩容易疲劳。

### B23 军事 / 战术（Military / Tactical）
- **定义**：仿军用显示与地图：橄榄绿、沙色，配琥珀或白字；模板字 (stencil)、坐标网格、北约兵种符号 (APP-6)、细分隔线和方括号。
- **CSS 特征**：深橄榄 `#2E3A23` 或黑底 + 半透明；1 px 细线 + 角标；等宽数字（`font-variant-numeric: tabular-nums`）；全大写；字体用 Black Ops One、Stardos Stencil（标题）、IBM Plex Mono（数据）；图标是几何化的军事符号；动效是硬切、数字跳变、雷达扫描。
```css
.tac { --amber:#FFC14D; background:rgb(10 14 8 / .7); color:#D9E0C8; border-left:2px solid var(--amber);
  font:500 13px/1.4 "IBM Plex Mono",monospace; text-transform:uppercase; letter-spacing:.08em;
  font-variant-numeric:tabular-nums; }
.tac h3 { font:400 18px "Black Ops One",sans-serif; color:var(--amber); }
```
- **代表游戏**：武装突袭 3、使命召唤：现代战争 (2019)、幽浮 XCOM 的战略层（公开常识）。
- **适用**：HUD ✓；菜单 ✓；地图、简报 ✓。
- **陷阱**：橄榄、沙色和环境同色，HUD 会"迷彩化"；全大写等宽字的阅读速度慢；敌我符号要配形状，不能只靠红蓝 [32]。

### B24 治愈系圆润（Cozy / Rounded）
- **定义**：大圆角、柔和投影、粉彩、圆体字、弹性动画，适合生活模拟和治愈类游戏。
- **CSS 特征**：圆角 16–28 px 或胶囊形；柔和大半径投影；奶油底色 `#FFF8EC` + 粉彩点缀；字体用 Nunito、Fredoka，中文用站酷快乐体或 Zen Maru Gothic 一类圆体；图标是圆润填充；动效是弹簧回弹 (overshoot) 和轻微摇摆。
```css
.cozy { background:#FFF8EC; color:#5A4636; border-radius:24px; padding:16px 20px;
  box-shadow:0 6px 0 #E8D7BF, 0 10px 24px rgb(90 70 54 / .18);
  font:700 17px "Nunito","ZCOOL KuaiLe",sans-serif; transition:transform .25s cubic-bezier(.34,1.56,.64,1); }
.cozy:hover { transform:translateY(-2px) scale(1.02); }
```
- **代表游戏**：集合啦！动物森友会（NookPhone 等圆润界面，公开常识）、A Short Hike、Unpacking（公开常识）。
- **适用**：HUD ✓；菜单 ✓；对话 ✓。
- **陷阱**：粉彩低对比，奶油底配浅棕字往往不到 4.5:1；所有东西都圆，层级就平了，主按钮要靠尺寸和饱和度拉开。

### B25 和风（Japanese Wa-style）
- **定义**：和纸纹理、墨绘笔触、朱红和蓝染（靛蓝）配色、传统纹样（麻叶、青海波）、明朝体、竖排。
- **CSS 特征**：和纸底 `#F5EFE0`；朱 `#D7402B`、藍 `#264D73`、墨 `#222`；青海波纹样用 `radial-gradient` 叠出；细框 + 角部装饰；明朝体 Shippori Mincho、Noto Serif JP；竖排 `writing-mode: vertical-rl`；动效是笔刷擦出（mask 动画）、花瓣飘落。
```css
.wa { background:#F5EFE0; color:#222; border:1px solid #222; outline:3px solid #F5EFE0; outline-offset:-6px;
  font:500 17px/1.9 "Shippori Mincho","Noto Serif JP",serif; }
.wa .seigaiha { background:radial-gradient(circle at 50% 100%, transparent 38%, #264D73 39% 42%, transparent 43%) 0 0/40px 20px; }
```
- **代表游戏**：大神 Ōkami（水墨绘卷风，公开常识）、对马岛之魂、只狼（公开常识）。
- **适用**：菜单、标题、地图 ✓；对话 ✓；HUD △（尽量极简，对马岛之魂几乎不显示 HUD，公开常识）。
- **陷阱**：日文字体缺简体中文字形，中文版要换字体（思源宋体）；纹样底上的文字要加底；朱红别和伤害提示混用。

### B26 手游抽卡金框（Mobile Gacha Gold Frame）
- **定义**：二次元或 MMO 手游常见：华丽金色描边、按稀有度分档的颜色和星级、强发光、粒子和红点通知。
- **CSS 特征**：用 `border-image` 九宫格做金框；金色多段渐变（`#FFF1B5 → #E0A940 → #8A5A12`）；稀有度色：金（最高）、紫、蓝、绿、白；外发光（`drop-shadow`）；粗无衬线 + 描边字；红点角标；动效是光效扫过、抽卡开箱和全屏特效。
```css
.gacha { border:10px solid transparent; border-image:url(gold-frame.png) 30 fill / 10px round;
  filter:drop-shadow(0 0 6px rgb(255 210 90 / .8)); }
.rarity-5 { background:linear-gradient(135deg,#FFF1B5,#E0A940 45%,#8A5A12); }
.badge { position:absolute; top:-4px; right:-4px; width:10px; height:10px; border-radius:50%; background:#FF3B30; }
```
- **代表游戏**：原神、崩坏：星穹铁道、Fate/Grand Order（公开常识）。
- **适用**：菜单、商店、角色养成 ✓；HUD △（通常换成更简洁的战斗 HUD）；对话 △。
- **陷阱**：金色叠在黄、橙背景上对比不足；红点泛滥，通知失去意义；`filter: drop-shadow` 和大量动画元素叠加时开销大；稀有度只靠颜色区分，对色盲不友好（要配星级或框形）[32]。

## C. 如何在工具中落地

思路是把"品类"当成一个**测试情境**：选一个品类，就得到一套镜头预设、一组测试片段和一套默认 UI 皮肤。美术风格（材质、光照、后处理）是另一个独立维度，两者自由组合，用同一份可读性检查清单打分。

### C.1 镜头预设（JSON 草案）

```jsonc

  "id": "arpg_fixed_iso",

}
```

`follow` 的字段直接借用 Cinemachine Position Composer 的概念（死区、软区、分轴阻尼、前瞻时间/平滑/忽略 Y）[16]；2D 的 `window2d` + `platformSnapY` 对应 Keren 的摄像机窗口和平台吸附 [1]；`comfort` 里的上限对应 Nesky 关于 FOV 变化和震屏的条目 [5]。

**迁移到引擎时的字段映射**

| 字段 | Three.js | Godot 4 | Unity（Cinemachine） |
|---|---|---|---|
| `fovDeg` | `PerspectiveCamera.fov`，本来就是垂直 FOV [15] | `Camera3D.fov`，配合 `keep_aspect = KEEP_HEIGHT` [12] | Lens 的垂直 FOV（字段名随版本变化，**未核实**） |
| `orthoHeight` | `top − bottom` | `Camera3D.size`（`KEEP_HEIGHT` 时就是全高，单位米）[12] | `orthographicSize` 是**半高**，要除以 2（公开常识） |
| 死区 / 软区 / 阻尼 / 前瞻 | 自己实现 | 2D：`Camera2D` 拖拽边距 + `position_smoothing_speed` [13]；3D 要自己写 | Position Composer [16] |
| `collision` | 自己写射线检测 | `SpringArm3D`（`spring_length`、`margin`、`shape`）[14] | Cinemachine 的碰撞扩展（组件名随版本变化，**未核实**） |
| 世界边界 | 自己实现 | `Camera2D.limit_*` [13] | Confiner 类扩展（公开常识） |

### C.2 UI 皮肤（设计 token 草案）

```jsonc
{
  "id": "jrpg_ff_window",
  "label": "JRPG 窗口 · 蓝渐变",
  "tokens": {
    "panel.bg": "linear-gradient(#3050c8,#101860)",
    "panel.border": "3px solid #e8e8f8",
    "panel.radius": "8px",
    "panel.shadow": "0 0 0 1px #000, inset 0 0 0 1px #000",
    "panel.backdropBlur": "0px",       // 只有玻璃拟态才非零
    "panel.nineSlice": null,           // 像素 / 拟物 / 金框用：{ "src": "frame.png", "slice": 8 }
    "text.color": "#ffffff",
    "text.shadow": "1px 1px 0 #000",
    "font.display": "\"Zpix\", \"Press Start 2P\", monospace",
    "font.body": "\"Zpix\", monospace",
    "font.letterSpacing": "0",
    "font.case": "none",               // none | upper
    "color.accent": "#ffd75e",
    "color.danger": "#ff5a5a",
    "color.ally": "#5aa9ff",           // 阵营色在 UI 和世界里共用同一套
    "color.enemy": "#ff9a3c",
    "cursor": "hand",                  // hand | triangle | bracket | glow
    "motion.textReveal": "typewriter", // none | fade | typewriter
    "motion.panelIn": "none"           // none | slide | pop | unroll | glitch
  },
  "contexts": { "hud": true, "menu": true, "dialogue": true },
  "a11y": { "minTextContrast": 4.5, "minNonTextContrast": 3.0, "reduceTransparency": true, "reduceMotion": true },
  "perf": { "backdropFilter": false, "svgFilter": false, "animatedGlow": false }
}
```

- **实现**：token 写成根节点 `.ui-skin` 上的 CSS 自定义属性。工具里固定放一组"样板组件"叠在 3D 视图上：血条 / 资源条、小地图框、对话框、菜单列表、提示框、按钮四态（常态、悬停、按下、禁用）、伤害数字。切皮肤只换变量，换品类只换样板组件的布局。
- **和世界色板联动**：`color.ally` / `color.enemy` 这类阵营色由 UI 和 3D 场景共用，可读性检查时一起参与色盲模拟，避免 UI 是橙蓝、世界却是红绿。
- **迁移到 Godot**：纯色 + 边框 + 圆角 + 阴影可以对应 `StyleBoxFlat`；九宫格对应 `StyleBoxTexture`；渐变要烘成贴图；`backdrop-filter` 在 Godot 里要用屏幕纹理模糊着色器自己做。这是建议的导出规则，属性名以 Godot 文档为准。
- **性能开关**：`perf` 字段让工具在"低端模式"下自动关掉 `backdrop-filter`、SVG 滤镜和发光动画，并提示该皮肤会因此损失哪些特征（见 B27 开销列）。

### C.4 可读性检查清单

| # | 检查 | 实现提示（Three.js） | 通过标准 | 依据 |
|---|---|---|---|---|
| 1 | **灰度** (grayscale) | 全屏后处理，亮度 = 0.2126R + 0.7152G + 0.0722B（线性 RGB，Rec.709 系数，公开常识） | 关键对象和局部背景的亮度比 ≥ 3:1 | 借 WCAG 非文本对比 [34]；TF2 环境"明度对比"原则 [6] |
| 2 | **眯眼 / 模糊** (squint / blur) | 降采样到 1/8 再放大，或高斯模糊，半径为视口高的 0.5–1% | 模糊后，最显眼的 3 个区域应该是玩家、威胁、目标 | Riot"最重要的东西最吸睛" [9] |
| 3 | **色盲模拟** (protanopia / deuteranopia / tritanopia + 全色盲) | 线性 RGB 乘 Machado 2009 的 3×3 矩阵（见下方代码）[33]；全色盲直接用 #1 | 阵营、稀有度、状态色两两之间的 OKLab 距离 ≥ 0.10（经验值）；**并且**有形状或符号冗余 | GAG：颜色不能单独承载信息、提供三种色盲预设 [32] |
| 4 | **只看剪影** (silhouette-only) | `scene.overrideMaterial` 换成纯黑 `MeshBasicMaterial`，背景纯白；或按语义类别渲染 ID 色 | 不看颜色也能认出职业、兵种、敌我 | TF2"只用剪影解决设计问题" [7]；Riot 剪影最重要 [9] |
| 5 | **距离 / 细节层级** (distance / LOD) | 自动把对象摆在 5/10/25/50/100 m，按 0.2 节公式算屏幕像素高，截图拼成对照条 | 关键对象 ≥ 16 px（经验值）；LOD 切换没有明显跳变 | Nesky：距离难判断 [5] |
| 6 | **明度分组** (value grouping) | 亮度直方图 + 3–5 档色调分离 (posterize) | 前景、玩法层、背景落在不同档；玩法对象不和环境同档 | TF2 环境原则 [6]；L4D 对比区域过多的教训 [8] |
| 7 | **特效压力** (VFX stress) | 粒子数 ×N、泛光拉满、叠加混合粒子堆叠 | 敌方前摇仍可读；画面平均亮度不超过 0.7（经验值） | Riot：视觉噪声累积、特效要短 [9][10] |
| 8 | **UI 叠加对比** | 采样每个 UI 面板下方背景的亮度分布，算"文字 vs 面板""面板 vs 背景"两组对比 | 正文 ≥ 4.5:1，大字和图标 ≥ 3:1 | WCAG 2.1 [34]；NN/g 关于玻璃拟态 [35] |
| 9 | **运动与舒适** | 记录 FOV 变化率、震屏幅度、头部晃动；后处理抖动图案是否在屏幕空间"游动" | 不超过预设的 `comfort` 上限 | Nesky #41–45 [5]；奥伯拉丁的回归的晕动问题 [29] |
| 10 | **光照鲁棒性** | 4 个时段 × 伽马 ±0.2 × 曝光三档，组合起来跑 1–8 项 | 所有组合下 1–8 项仍然通过 | 恐怖和生存类的暗部问题（A7/A8） |

```glsl
// Machado, Oliveira & Fernandes 2009，严重度 1.0（二色视）[33]
// GLSL 的 mat3 按列填写，所以下面每行是原表的一列；输入、输出都是线性 RGB
// （在线性空间做是常见实现惯例，原页没有明说，未核实）
const mat3 PROTAN = mat3( 0.152286, 0.114503,-0.003882,  1.052583, 0.786281,-0.048116, -0.204868, 0.099216, 1.051998);
const mat3 DEUTAN = mat3( 0.367322, 0.280085,-0.011820,  0.860646, 0.672501, 0.042940, -0.227968, 0.047413, 0.968881);
const mat3 TRITAN = mat3( 1.255528,-0.078411, 0.004733, -0.076749, 0.930809, 0.691367, -0.178779, 0.147602, 0.303900);
vec3 simulateCVD(vec3 linRGB, mat3 M) { return clamp(M * linRGB, 0.0, 1.0); }
```

**呈现方式建议**
- 每项检查输出 0–1 分，按"风格 × 品类预设"出一张可读性雷达图，方便横向比较风格。
- 提供分屏 A/B 视图：左边原图，右边灰度、色盲、剪影或模糊之一，拖动分割线对比。非美术背景的开发者往往一眼就能看出问题。
- 不通过的检查，直接在画面上框出对应对象（例如"拾取物 #3 与背景亮度比 1.4:1"），并链接到本文对应品类的"可读性规则"条目。
