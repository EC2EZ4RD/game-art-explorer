# 游戏美术风格探索台：产品愿景与详细需求

> 文档日期：2026-10-13  
> 文档用途：重新明确产品目标，供后续产品设计、美术研究、技术选型与开发使用。  
> 文档状态：用户提供的需求原文存档（2026-10-13）。实现计划见本仓库外的计划文件与 `docs/survey/`。  
> 用户追加要求（2026-10-13）：覆盖要大而全并做好调研；能力边界不预设、工具要能持续补充；网页上的风格要便于迁移到 Godot 等引擎；起点是"低多边形微缩沙盒"灵感提示词（见文末附录）。

---

## 1. 用第一人称说清楚：我真正想做什么

我是一个不熟悉美术的独立游戏开发者。

我看到喜欢的游戏画面，能够感到"好看""舒服""有氛围"，却不知道这种感觉由什么构成，也不知道怎样把它描述成 AI 或开发者能够执行的要求。

我需要一个**游戏美术风格探索与调参工具**。它应该让我先看到足够丰富的视觉可能性，再通过亲手改变场景、形状、材质、光影、颜色、镜头等因素，逐渐找到自己的偏好。

我希望它帮助我完成这样的过程：

**看见不同方向 → 找到感兴趣的例子 → 拆解差异 → 在真实场景中调参 → 对照比较 → 保存偏好 → 得到准确、可复用的美术描述。**

真实游戏案例、术语解释、表格和提示词，都应该围绕这个过程服务。产品的核心始终是能够操作、能够观察变化的探索台。

我不希望每次尝试一种效果，都重新生成一张图或一个模型。基础素材应尽量生成或准备一次，之后通过参数、模块组合和必要的资产变体反复探索，减少生成成本。

最终，我不仅要拿到一段提示词，还要理解：**我喜欢的到底是造型、画法、色彩、光线、空间，还是它们之间的关系。**

## 2. 已确认的要求与尚未锁定的方案

### 2.1 已确认的用户要求

| 方面 | 明确要求 |
| --- | --- |
| 使用者 | 对美术知识和风格分类不熟悉，需要通过视觉与操作学习 |
| 核心形态 | 优先做 3D 游戏美术探索台，可以用同一场景比较不同风格 |
| 核心行为 | 真正调参、即时观察、比较结果，而不只是浏览预设名称 |
| 内容广度 | 覆盖多种游戏品类、场景、文化题材、媒介和视觉语言 |
| 场景范围 | 不能只围绕海岛，需要考虑游戏中的各类空间 |
| 游戏案例 | 数量要丰富，有真实截图和可追溯来源 |
| 案例发现 | 参考 Steam 热卖、愿望单，以及通过 SteamPeek 扩展的相关游戏 |
| 学习表达 | 用表格对应"术语解释、视觉效果、可复用提示词" |
| 重点补充 | 中式风格、水墨、工笔淡彩、体素等必须纳入覆盖规划；这些只是举例 |
| 内容组织 | 需要重新设计展示层级，便于从游戏品类与美术方向进入 |
| 预设与部件 | 需要较丰富的预设和可复用部件，支持继续混搭与修改 |
| 素材成本 | 可使用 AI 图像生成服务 准备基础素材，之后优先本地复用 |

### 2.2 本文提出、但未被用户逐项确认的建议

以下属于后续设计建议：具体界面布局、参数分组名称、案例卡字段、比较模式、内容更新机制、阶段划分与资产组织方式。

它们用于让需求可执行，不表示用户已经同意所有细节。

### 2.3 对最初游戏提示词的理解

最初的"治愈手办风沙盒探索游戏"是一份帮助说明需求的例子。它展示了技术词汇如何组成画面要求，但最终产品不应被限制成一个海岛沙盒游戏。

最初例子中的"禁止方块"只适用于那个特定视觉方案。后来用户明确要求探索体素，因此探索台必须允许体素作为一个独立方向。

Three.js、单文件 HTML、某种描边算法，也不能反过来决定探索范围。后续技术方案应根据需求取舍，并公开能力边界。

## 3. 产品要解决的问题

### 3.1 看不见可能性

新手通常只能说出少数熟悉的风格名，不知道还有哪些选择。只提供"手办、赛博朋克、水彩"等几个按钮，无法建立足够宽的视觉认识。

产品需要提供有组织的发现入口，让用户能够遇见自己原本不会搜索的方向。

### 3.2 不知道差异来自哪里

两张图同时换了角色、地形、光线和颜色，新手很难判断自己喜欢哪一部分。

产品需要提供固定条件、单项修改以及受控比较，让变化原因清楚可见。

### 3.3 不会把感受翻译成要求

"不要油腻""更有手绘感""像一个精致模型"都可能指向不同问题。产品应帮助用户把感受进一步拆成可观察、可讨论的选择。

例如"更像模型"可能来自尺度参照、镜头、比例、材质、灯光和景深，不应自动翻译成某一个 Shader。

### 3.4 漂亮画面未必适合游戏

一张静态图可能很吸引人，但角色移动后看不清、交互物不突出、室内遮挡严重，或资产难以持续制作。

探索台需要帮助用户初步检查实际游戏条件，而不仅是欣赏宣传视角。

### 3.5 试错成本太高

如果每次换风格都需要重新生成素材，用户会因为生成成本和等待时间而减少尝试。

产品应把日常探索建立在可复用素材和实时参数上，只有缺少关键结构或媒介素材时，才进入新的素材制作流程。

## 4. 产品定位与边界

### 4.1 核心定位

**面向美术新手的、以真实游戏参考为入口、以实时视觉实验为主体的游戏美术方向探索工具。**

核心价值分为三层：

1. 帮用户发现更多可能性。
2. 帮用户通过操作理解差异。
3. 帮用户留下可以继续制作的方向与规则。

### 4.2 各模块的关系

| 模块 | 主要作用 | 与调参台的关系 |
| --- | --- | --- |
| 游戏参考库 | 展示真实作品中的视觉选择 | 为实验提供观察对象与出处 |
| 风格地图 | 建立分类感，发现遗漏方向 | 为参数、资产与场景提供入口 |
| 场景和部件库 | 提供不同空间与对象 | 为风格变化提供合适载体 |
| 实时调参台 | 修改并观察画面 | 产品主体 |
| 教学词条与表格 | 解释变化为什么发生 | 紧贴当前操作与案例 |
| 比较和收藏 | 识别、保留个人偏好 | 把随意尝试变成可追溯探索 |
| 提示词与规范导出 | 将结果转成可复用语言 | 探索完成后的产物 |

### 4.3 本产品不以这些结果作为完成标准

- 收集了很多游戏截图，但不能方便地进入实验。
- 增加了很多风格名称，但实际只改变整体色调。
- 堆积了大量术语，却需要先学习术语才能操作。
- 展示了漂亮的静态示意图，却没有相应实时能力。
- 能自动拼接提示词，但提示词与实际画面不一致。
- 做成一个完整沙盒游戏，却没有解决风格探索问题。

这些可以是辅助内容或其他产品目标，不能替代本产品的核心任务。

## 5. 应如何理解"美术风格"

### 5.1 原来的组合思路有用，但不能当作完整分类

"场景 + 地貌/网格 + 材质/着色 + 描边/线条 + 灯光/相机 + 配色/UI"适合描述一部分三维渲染配置。

作为探索产品，它还缺少：文化题材与世界逻辑；形状语言、比例和细节分配；2D、3D、体素等媒介结构的区别；构图、空间组织与画面层级；动画、特效和反馈节奏；实际玩家镜头与游戏可读性；资产生产方式和复用条件。

其中有些因素是连续参数，有些需要选择结构、切换资产或改变渲染方式。不能把所有因素都做成一个百分比滑块。

### 5.2 建议采用的分类层次

| 层次 | 回答的问题 | 示例 |
| --- | --- | --- |
| 游戏条件 | 玩家怎样看、怎样操作？ | 俯视战斗、横版跳跃、第三人称探索、室内解谜 |
| 世界与文化 | 这是怎样的世界？ | 中式市井、东方幻想、工业科幻、欧洲乡村 |
| 场景与空间 | 行为发生在哪里？ | 街巷、庭院、森林、地牢、工厂、卧室 |
| 视觉语言 | 怎样概括物体？ | 圆润、尖锐、夸张、几何化、装饰性、疏朗 |
| 媒介与表示 | 图像怎样构成？ | 三维模型、二维手绘、像素、体素、纸片混合 |
| 表面与渲染 | 光、颜色和边缘怎样表现？ | 连续明暗、卡通分阶、绘画表面、线稿、抖色 |
| 时间与反馈 | 运动时是什么感觉？ | 流畅、定格节奏、夸张弹性、克制反馈 |
| 情绪与识别 | 希望玩家感到什么、先看到什么？ | 宁静、压迫、孤独、主角突出、路径明确 |
| 制作约束 | 这套风格怎样持续做下去？ | 模块复用、贴图规格、动画方式、成本与性能 |

这些层次允许组合，并不存在一棵可以把所有作品唯一归类的"标准风格树"。

例如，中式庭院可以用体素、工笔、低模、写实、纸艺等不同方式表现；水墨也不必永远搭配古代中国场景。

### 5.3 界面应区分两种 UI

**探索工具自身的界面**首先服务清晰和易用，不必随着每次实验剧烈变形。

**被研究游戏的 UI/HUD**可以作为风格的一部分参与实验，例如图标、血条、对话框、地图和交互提示。

游戏 UI 与环境配色需要协调，但不应合并成一个"配色/UI"参数。

## 6. 使用流程与展示层级

### 6.1 推荐的主流程

1. **选择进入方式**：从喜欢的感觉、游戏案例、游戏品类、场景或已有配方进入。
2. **选一个观察方向**：先看真实例子，知道当前要观察什么。
3. **选择实验载体**：固定同一场景，或者选择与目标玩法相符的场景。
4. **应用可执行配方**：载入所需资产、材质和初始参数。
5. **修改一个因素**：观察实际变化与旁边的解释。
6. **进行比较**：保存 A、调整 B，或排列多个受控变体。
7. **记录偏好**：指出喜欢的具体部分，以及不想要的部分。
8. **导出结果**：保存可复现状态、画面、参考来源与美术描述。

### 6.2 允许直接开始，不强制先选风格名

一个不知道"赛璐璐"是什么的用户，仍应能通过"明暗更干脆""表面更像纸""物体更圆润"等入口开始。一旦用户产生变化，工具再告诉他对应术语和实现条件。术语知识应在使用中逐渐出现，而不是成为进入门槛。

### 6.3 建议的信息层级

| 层级 | 展示内容 | 设计要求 |
| --- | --- | --- |
| 第一层：正在看的结果 | 大画面、当前场景、主要操作、A/B | 持续可见，始终知道自己在调什么 |
| 第二层：起点选择 | 游戏参考、场景、风格家族、配方、部件 | 可快速切换，避免反复穿过多层弹窗 |
| 第三层：当前维度 | 参数、示例、小图、白话解释 | 每次集中展示相关项 |
| 第四层：深入理解 | 中英文术语、技术原理、案例出处、制作条件 | 按需展开 |
| 第五层：成果管理 | 收藏、实验历史、描述、素材清单、导出 | 不打断探索 |

### 6.4 防止"资料库压过调参台"

游戏截图应能与当前实验画面方便对照。查看术语后应能直接回到对应控件。搜索结果、风格卡和术语卡都应说明：它能带来怎样的实验、需要什么载体、实际支持到哪一步。

## 7. 调参系统：需要覆盖的维度

| 维度 | 新手看到的说法 | 可探索的内容 | 实现所需条件 |
| --- | --- | --- | --- |
| 场景结构 | 空旷一点、围合一点、路更清楚 | 路径、地标、房间、院落、纵深、疏密 | 场景模块或程序布局 |
| 地貌与空间尺度 | 山更陡、地面更平、空间更高 | 起伏、坡度、悬崖、河道、层高、尺度参照 | 地形生成与结构资产 |
| 形状语言 | 更圆、更尖、更厚重 | 曲率、棱角、大中小形关系、负形 | 可变形模型或同类变体 |
| 比例 | 更像玩具、更修长、更笨重 | 头身比、四肢、门窗、树冠、道具体量 | 正确的变形关系与骨骼/模块 |
| 几何表示 | 光滑、折面、块状 | 轮廓复杂度、网格密度、体素尺度 | 不同几何表示方式 |
| 细节频率 | 简洁一些、细节集中一些 | 纹理密度、装饰密度、磨损范围 | 分区控制、细节层或资产层级 |
| 材质属性 | 像泥、木头、金属或玻璃 | 粗糙度、反光、透明、厚度观感 | 相应材质模型；不能只换颜色 |
| 光照着色 | 明暗连贯或分成色块 | 色阶、阈值、阴影颜色、明暗交界 | 兼容的 Shader 和法线 |
| 线条与边缘 | 细线、粗线、彩色线、软边 | 外轮廓、内部结构线、距离变化、断续感 | 区分几何、图像与绘画线条方案 |
| 表面媒介 | 纸面、笔触、版画、像素 | 纸纹、笔触方向、渗边、网点、像素规则 | 专用纹理、资产或媒介管线 |
| 色彩系统 | 颜色更克制、主角更醒目 | 主辅色、强调色、面积比例、冷暖与明度 | 分对象/区域色彩管理 |
| 灯光与阴影 | 午后、阴天、室内、逆光 | 方向、光源尺寸、补光、阴影与接触关系 | 场景对应的光源和阴影 |
| 镜头与构图 | 像沙盘、像亲身进入、人物更大 | 投影、视角、焦距、距离、占屏、景深 | 相机系统与相应效果 |
| 空气与环境 | 清透、潮湿、风大、下雪 | 距离雾、天气、风、水面与环境运动 | 对应环境系统，明确真假体积效果 |
| 动画与运动 | 流畅、顿挫、弹性、沉重 | 姿势、帧节奏、缓动、次级运动 | 动画资产、绑定与运动规则 |
| 特效与反馈 | 命中更清楚、危险更好认 | 拾取、命中、轮廓提示、轨迹、危险区 | 最小交互测试与 VFX |
| 游戏 UI | 更像手绘、符号更清楚 | 字体、图标、边框、提示、动效 | 独立的 HUD 样本与主题 |
| 可读性 | 更容易找到主角和出口 | 图底关系、明度分组、交互对比 | 灰度、剪影、缩略图与动态检查 |

### 7.1 参数控件必须解释四件事

- 它作用于什么对象或层次。
- 往两端调，肉眼会看到什么变化。
- 在当前场景、材质或资产上是否有效。
- 哪些效果超出它的能力。

例如：切换到不使用粗糙度的着色方案时，应解释该参数为什么不生效，而不是保留一个看似能用的滑块。

### 7.2 参数类型

| 类型 | 合适的例子 | 不合适的用法 |
| --- | --- | --- |
| 连续参数 | 比例、光照角度、粗糙度 | 用一个"水墨程度"代替全部水墨语言 |
| 离散档位 | 明暗层数、像素网格规格 | 档位不同但画面几乎不变 |
| 结构选择 | 正交/透视、模型/体素、室内/室外 | 只改标签，不改结构 |
| 资产变体 | 不同屋顶、人物比例、树木造型 | 任意拉伸一个模型冒充不同文化建筑 |
| 组合规则 | 配色角色分工、布局密度、材质分配 | 无规则地随机所有项目 |
| 情境测试 | 移动、遮挡、拾取、夜间 | 用静态截图代替运动表现 |

### 7.3 参数之间的依赖

参数可以独立探索，但不必假装相互没有影响。产品应说明相机距离对线宽与细节的影响、描边对体素轮廓的影响、纸纹对运动稳定性的影响，以及灯光对材质判断的影响。切换一种需要新资产或新管线的表现时，应说明会替换什么，并允许保留其他可兼容条件。

## 8. 场景系统：让不同游戏空间成为可用的实验载体

### 8.1 场景不能只做成同一块底座上的摆件排列

室内需要墙、地面、家具、开口与遮挡关系；街道需要道路、建筑立面和尺度；地下空间需要顶面或围合感、通路与局部照明。它们的差异必须进入空间结构。圆形沙盘可以是一种观察方式，但不能成为所有场景的强制形态。

### 8.2 建议的场景覆盖地图

| 大类 | 需要纳入的空间方向 | 主要验证什么 |
| --- | --- | --- |
| 自然开放空间 | 草原、丘陵、花田、旷野 | 大色块、尺度、远景与路径 |
| 林地 | 阔叶林、针叶林、竹林、密林 | 遮挡、植被语言、光斑与层次 |
| 山地 | 峡谷、山路、峭壁、洞口 | 垂直空间、地形轮廓、远近关系 |
| 干旱地貌 | 沙漠、戈壁、绿洲、风蚀地貌 | 留白、风化、暖色、强光 |
| 寒冷环境 | 雪原、冻湖、冰洞、雪村 | 高明度、冷暖、材质区分 |
| 水域边缘 | 海岸、港口、河岸、湖畔、湿地 | 水陆交界、反射、透明与湿度 |
| 水下 | 浅海、珊瑚、深海、沉船 | 水下可见度、色衰减、悬浮运动 |
| 地下自然空间 | 洞穴、矿道、晶洞 | 局部照明、封闭感、识路 |
| 乡村与农场 | 农舍、田地、果园、牧场 | 生产痕迹、秩序与自然关系 |
| 城镇与市井 | 商业街、窄巷、广场、市场 | 街道层级、招牌、建筑密度 |
| 大型城市 | 天际线、交通设施、住宅街区 | 垂直密度、尺度、城市节奏 |
| 中式空间 | 庭院、园林、民居、祠堂、山门 | 建筑语法、院落、文化依据 |
| 历史与幻想建筑 | 城堡、教堂、神殿、村堡 | 建筑轮廓、仪式感与材质组织 |
| 地牢与遗迹 | 回廊、地下室、墓室、废墟 | 路线、危险、明暗引导 |
| 生活室内 | 卧室、厨房、客厅、书房 | 家具尺度、材料、生活叙事 |
| 公共与商业室内 | 商店、酒馆、车站、展厅 | 动线、焦点、物品陈列 |
| 工业空间 | 工厂、车间、仓库、矿场 | 模块重复、机械连接、信息密度 |
| 科幻设施 | 飞船舱室、空间站、实验室、基地 | 科技构形、模块、指示与灯光 |
| 废弃与末日空间 | 废城、荒废室内、污染区 | 使用痕迹、破损与情绪 |
| 超现实空间 | 漂浮结构、不可能建筑、梦境舞台 | 抽象形体、非日常尺度、构图 |
| 交通与赛道 | 公路、山路、城市赛道、轨道 | 速度、弯道识别、远景节奏 |
| 战斗与竞技空间 | 竞技场、掩体场、Boss 房 | 敌我识别、危险区、行动余量 |
| 桌面与界面空间 | 卡牌桌、棋盘、物品陈列台 | 平面与立体混合、符号、UI |
| 宏观观察空间 | 经营地图、战术地图、星图 | 缩放、密度、层级与信息抽象 |

这是扩展目录，不要求第一版一次完成所有空间。未覆盖的方向必须可见，不能因为没有做出来就从分类中消失。

### 8.3 四种实验载体

1. **对象测试台**：单个角色、建筑、树木或道具，适合观察形状、材质与线条。
2. **受控母场景**：包含角色、路径、建筑、植被、石材与交互物，用于公平比较。
3. **情境场景**：室内、街巷、森林、庭院等，验证风格在真实空间关系中是否成立。
4. **玩法测试片段**：最小移动、战斗、拾取、建造或缩放实验，检查实际观看条件。

"同一场景比较风格"与"提供多种场景"应同时成立：前者用于找原因，后者用于检查适用范围。

### 8.4 场景切换的行为约定

- 默认保留当前可兼容的风格参数。
- 说明会替换的空间结构、资产与灯光布置。
- 使用场景合理默认值时，列出发生的变化。
- 支持撤销或回到之前的完整状态。
- 允许明确选择"只换场景"或"应用场景推荐整套配方"。

## 9. 风格覆盖：用多维地图避免漏项

### 9.1 覆盖不能只靠数量证明

几十个名称可能只覆盖一种三维卡通语言的不同配色。用户所说的"全面"，应转成可以检查的覆盖结构：

**游戏品类 × 场景类型 × 文化题材 × 视觉/媒介方向 × 可实验能力**

不必穷举所有排列，但应看得出哪些区域有案例、哪些有实时实验、哪些缺资产、哪些尚未研究。

### 9.2 文化、世界与题材轴

至少应持续研究以下方向及其内部差异：

- 中式市井、园林、乡村、民俗、武侠、仙侠、东方幻想。
- 欧洲乡村、中世纪聚落、哥特、古典神话、维多利亚、蒸汽工业。
- 当代生活、城市日常、工业设施、现实乡野。
- 工业科幻、太空探索、复古未来、赛博都市、生物科技。
- 末日、废土、暗黑幻想、童话、超现实。

这些名称不是单一画法。具体文化和历史判断需要对应资料，不能通过几件符号化道具替代。

### 9.3 形体、媒介与技法轴

| 方向组 | 应展开的分支与观察点 |
| --- | --- |
| 写实与风格化三维 | 可信比例、概括程度、细节频率、材料关系 |
| 动画式三维 | 圆润体块、夸张比例、姿势、表情、弹性 |
| 动漫与漫画语言 | 角色设计、分阶明暗、线条、关键姿势、图形特效 |
| 绘画感三维 | 手绘表面、笔触方向、色块塑形、边缘控制 |
| 低多边形与几何设计 | 轮廓取舍、切面、负形、简化规则 |
| 体素 | 体素尺寸、层级、阶梯轮廓、模块和画面噪声 |
| 像素与二维/三维混合 | 像素密度、有限色板、Sprite、像素运动规则 |
| 复古三维 | 低分辨率贴图、抖色、几何与采样特征、时代限制 |
| 水墨 | 墨色层次、虚实、留白、笔势、干湿与边缘 |
| 工笔与淡彩 | 细谨内部线描、造型、分染、罩染、线色关系 |
| 水彩与水粉 | 透明性、覆盖性、纸底、色面和渗边的不同组织 |
| 油画与厚涂 | 笔触、厚薄、方向、边缘与色面 |
| 素描与版画 | 排线、黑白、刻痕、疏密与明度组织 |
| 平面与海报 | 限色、符号、负形、版式、轮廓与信息层级 |
| 拼贴、剪纸与纸片 | 分层、裁切、材料边缘、投影与运动 |
| 黏土、木偶、毛毡、实物微缩 | 材料痕迹、尺度、表面、定格与摄影语言 |

对于以二维制作规则为核心的方向，应选择合适的载体，如分层素材、卡片、Sprite 或混合场景。不能为了维持"全部是同一个 3D 模型"而把这些差异抹掉。

### 9.4 情绪与体验轴

可作为发现入口的词包括：治愈、宁静、清冷、孤独、庄严、神秘、压迫、诡异、活泼、梦幻、怀旧、粗粝、轻盈、幽默。情绪标签需要进一步关联到可以观察的因素。不能把"治愈"固定等同于马卡龙配色，把"恐怖"固定等同于降低亮度。

### 9.5 能力状态应分开记录

| 状态 | 含义 | 产品行为 |
| --- | --- | --- |
| 可实时实验 | 所声明的具体效果已经作用于画面 | 提供参数、条件和比较入口 |
| 需要专用素材 | 结构或媒介无法只靠现有模型表达 | 说明缺少什么，载入素材后再实验 |
| 局部实验 | 只实现该方向的一部分因素 | 明确可调部分与尚缺部分 |
| 参考研究 | 有案例和分析，尚无对应实验能力 | 进入资料层，不能伪装成完整可用配方 |
| 待补充 | 分类中存在，但案例或能力不足 | 显示缺口，不虚构代表案例 |

状态应记录到具体能力，例如"能调外轮廓，不能生成内部工笔线描"，而不是笼统写"支持国风"。长期目标是扩大实际实验能力。

| 游戏品类 | 建议的测试条件 | 重点检查 |

## 11. 游戏案例的发现、来源与分析

### 11.1 研究对象

以独立游戏和中等体量作品为主要研究对象，兼顾有代表性的其他作品，用于补充某种视觉语言。不能根据画风或商店标签直接判断团队规模、预算或"独立"身份。缺少可靠资料时，应保留未知状态。

### 11.2 发现路径

1. 从 Steam 热卖和愿望单中发现受到关注的候选。
2. 从已知游戏进入 SteamPeek，寻找相近玩法或标签的候选。
3. 查看候选游戏的实际画面和资料，独立分析美术特征。
4. 通过评价、开发者资料、评测等补充理解。
5. 对分类地图中的空缺做定向补充，避免热门榜单决定全部覆盖范围。

案例是否入选，取决于它是否能说明一种有价值的视觉选择，不只是排名是否高。

### 11.3 四种依据必须分开

| 依据 | 可以说明什么 | 不能直接说明什么 |
| --- | --- | --- |
| 热卖榜 | 特定范围和时间的销售关注度 | 美术质量、长期销量或全部成功原因 |
| 愿望单榜 | 特定范围和时间的期待度 | 已发售质量、玩家体验或最终表现 |
| 玩家好评 | 玩家对整作游戏的评价 | 美术专项评分 |
| SteamPeek 关联 | 基于标签等方式发现相近候选 | 两款游戏拥有相同画风 |

若使用"美术好评"标签，应有直接评价视觉表现的外部证据。没有专项证据，就只标记整体好评。开发者分享和官方技术资料单独归为制作依据。

### 11.4 截图要求

- 必须是真实游戏画面，并提供对应来源。
- 优先官方商店、开发者网站、官方媒体资料或开发者发布内容。
- 尽量使用能看清玩法画面的截图，避免用海报、封面或评分宣传图替代。
- 区分游戏截图、概念原画、宣传渲染、预告片帧和编辑示意。
- 一张图不够解释时，补充近景、远景、室内、室外或不同光照条件。
- 图片链接失效时显示来源与状态，不用生成图冒充补位。
- 游戏素材作为学习参考展示；其使用范围与项目自有可复用资产分开记录。

### 11.5 单个案例的建议字段

游戏身份、玩法与观看条件、画面资料（截图/图注/来源/核对日期）、入选原因、视觉拆解、观察依据、技术可信度（官方证实/画面推断/未知）、可迁移规则、对应实验、能力边界、提示词（避免只写"像某游戏"）。一款作品可以属于多个方向。

## 12. 预设与配方系统

| 概念 | 作用 | 例子 |
| --- | --- | --- |
| 风格家族 | 帮用户发现与理解 | 体素、绘画感三维、微缩、漫画 |
| 可执行配方 | 在某些资产和场景上产生明确效果 | 固定体素尺度、限色色板、特定灯光与镜头 |
| 用户实验 | 用户修改后的完整结果 | 某场景、资产组合、参数、时间与个人备注 |

一份有效配方应包含：想得到的画面特征与重点观察位置；适用的场景、镜头和资产类型；必须载入的几何变体、纹理或材质；影响结果的完整参数；建议先调的两三项因素；与相邻配方的主要区别；来源案例和观察依据；已实现与未实现的部分；可复现状态和版本信息。

优先扩展视觉机制明显不同的方向，再增加同一机制下的细分变奏。"晴天、黄昏、月夜"是光照变奏，不应被计为三套不同的媒介风格。

混搭：用户应能选择"这个方案的造型 + 另一个方案的线条 + 自己的配色"，并锁定不想改变的维度。依赖不同表示方式时需要说明混合后的结构与边界。

## 13. 部件与基础素材：为复用而准备

"只生成一次"应理解为每个可复用基础资产尽量少重复生成，不是整个产品只能使用一个通用模型。

部件组：角色、建筑结构、建筑变体（中式、历史聚落、现代、工业、科幻）、植被、地质与地面、生活道具、功能与交互物、工业与科幻、交通与大型物件、叙事与装饰、媒介素材（纸纹、笔触、排线、网点、像素与分层素材）、UI 与特效。

资产约定：同类资产使用一致的尺度、坐标、命名与材料槽约定；颜色、可变比例和材质分区尽量可控制；重要轮廓提供有意义的变体；需要表面纹理、UV 或动画的方向在基础资产阶段留好条件；记录来源、版本、生成成本及可复用范围；导入资产需要知道哪些效果可用。

AI 图像生成服务 适合补充有辨识度的基础角色、建筑、道具或其他需要生成服务提供的素材；程序化几何适合可规则构建的测试件与模块；两者按需要配合。

## 14. 边看边学的解释系统

推荐的展示顺序：**白话操作 → 画面变化 → 专业术语 → 可复用描述 → 实现条件。**

面向新手的主要输出应描述想看到的效果；具体 Shader、描边算法或阴影过滤方式放在技术层。"阴影边缘清楚，接触关系明确"是视觉要求；PCF 是一种阴影采样过滤方法，不能单凭这个名称保证硬阴影。PBR 不等于写实，NPR 也不等于卡通分阶。

## 15. 比较、探索与偏好记录

受控比较：固定场景、资产、种子、时间与镜头，只改变选定变量；A/B 切换或并排；多参数变体小图；单维度扫描；同一配方跨场景；同一场景跨配方。

诊断视图：灰度、剪影、简化明度与缩略图是观察工具，不应污染最终配方；可读性检查同时包含静态与动态情况。

偏好记录：喜欢哪里、不喜欢哪里、希望保留的因素、下次只想改变的因素；可形成个人视觉方向板，但不自动断言用户只喜欢某一类风格。

受约束的探索：随机探索允许锁定维度，并把变化限制在可理解范围内；每次随机结果可撤销、可复现。

## 16. 提示词、配方与美术规范导出

| 输出 | 用途 | 内容约束 |
| --- | --- | --- |
| 实际画面说明 | 描述当前实验结果 | 只写当前确实生效的选择 |
| 目标美术 Brief | 指导后续美术或生成工作 | 可以包含尚未实现的愿景，但明确缺口 |
| 技术实施规格 | 交给开发者或代码 AI | 记录资产依赖、参数、管线、条件与待实现项 |
| 可复现配方 | 再次打开同一实验 | 保存场景、素材引用、状态与版本，而不只有色值 |

提示词组织顺序：游戏品类与视角 → 场景、主体、文化与空间结构 → 视觉目标与情绪 → 形状、比例、轮廓与细节 → 媒介、材质、明暗和线条 → 色彩、灯光、构图与环境 → 动画、特效、UI 与可读性 → 素材、性能、成本与复用约束 → 参考来源、需要避免的效果和验收方式。根据目标任务省略无关项。

可复现配方需要保存：场景及其版本、对象与资产引用、变体、变换、材质与纹理、参数、镜头、光照、环境、随机种子、时间/动画状态、依赖版本、参考来源和用户备注。导入缺少素材时应列出缺失项。

## 17. 成本与技术原则

在素材与依赖已准备好的前提下，拖动参数、应用已有配方、切换已缓存素材、A/B、诊断视图、截图和模板化描述导出，在本地完成，不触发新的 AI 生成调用。需要 AI 进一步分析或生成时，应作为单独、可识别的动作。

新素材生成流程：确认现有素材是否能满足目标 → 说明缺少的结构、媒介或表面信息 → 列出拟生成资产、规格与预计复用方式 → 展示可获得的费用信息和本次生成范围 → 由用户主动发起新增生成，完成后保存并登记资产。

技术选型服从能力：先验证代表方向的画面质量、运动稳定性与性能，再批量扩展预设；不把一个引擎 API 的存在当成某种完整艺术效果已经实现。

## 18. 建议的阶段与优先级（原文摘要）

- 阶段 0：需求与视觉标准。
- P0：验证真正的探索闭环——以画面和调参为中心的工作区；结构不同的实验载体（自然、建筑聚落、室内/封闭）；几何、材质/明暗、色彩、灯光、镜头等关键维度有真实变化；案例、解释表格、参数入口互通；A/B、撤销、状态保存与恢复；实际画面说明与目标描述分离；常规实验不重复请求生成服务。
- P1：扩大覆盖并提高学习效率（Steam/愿望单/SteamPeek/美术证据、场景部件文化结构、中式/水墨/工笔/像素/体素/复古三维等实验条件、更多独立机制配方、扫描与锁定探索、玩法片段、动画特效与游戏 UI、收藏与成本记录）。
- 后续：完整二维规则、复杂绘画与线条管线、用户自带资产适配、多场景一致性、生产规范包、更丰富的动态测试。

## 19. 验收标准

必须通过：新手能开始；调参真实有效；能解释变化；风格差异有内容；场景差异有结构；比较可信；案例真实；市场证据准确；分类不混乱；能力不冒充；输出可继续使用；成本可理解。

具体使用任务：
- **任务 A 从零发现偏好**：只选择"安静、自然、简洁"，看到若干机制不同的方向，进入场景修改参数，解释并保存喜欢的变化。
- **任务 B 同一空间探索不同表现**：保持庭院布局，比较圆润微缩、低多边形与体素表示，说明替换了哪些几何或资产。
- **任务 C 验证跨场景适用性**：同一配色与表面方向用于森林、街道和室内。
- **任务 D 区分"看起来像"与"实际做到"**：选择工笔淡彩，解释所需内部线描、设色与素材条件，不把浅色模型当完成结果。
- **任务 E 从热门作品继续探索**：从榜单游戏进入，经 SteamPeek 找到相关候选，辨认相近与不同的美术选择。
- **任务 F 低成本反复实验**：连续更改光照、形状、颜色与镜头并保存多个方案，不重新请求生成，导出后能恢复。

需要重点避免：用案例数量替代交互改善；同一底座同一镜头的场景排列；整体滤镜代替结构媒介造型差异；参考方向误标为可用预设；术语越来越多路径越来越难；为沿用旧代码压缩范围；所有实验围绕一个基础模型。

## 附录：灵感提示词（用户提供，2026-10-13）

【核心创意】
将《我的世界》（Minecraft）的沙盒探索玩法，全盘迁移到现代高品质 NPR（非真实感卡通渲染/微缩手办）美学中。
⚠️ 绝对禁止使用任何立方体/方块（Strictly NO Voxels, NO Cubes, NO Minecraft block textures）！我们要的是像《塞尔达传说：织梦岛》重制版与《Messenger》那样自然起伏的低多边形微缩沙盒。

【一、视觉与渲染标准（严格执行）】
1. 地貌结构：使用平滑起伏的低多边形网格（PlaneGeometry + 连续分形 Perlin/Simplex 噪声）。使用 toNonIndexed() 实现清脆利落的面着色（Faceted Flat Shading），禁止粗糙的像素方块。
2. 着色管线：全局使用 MeshToonMaterial，绑定 Canvas 动态生成的 3 阶灰度阶梯渐变（Gradient Map），呈现干净干练的二分/三分阶梯硬光影。
3. 描边工艺：全场景重要物体（地形、植被、角色）必须基于反向外壳技术（Inverted Hull: 沿平滑法线微量膨胀 + BackSide 黑色渲染），打造手办线稿轮廓。
4. 色彩调色板：采用高饱和纯色。海滨浅滩柠檬黄、低地苹果绿、高山松石青、雪顶纯白，水体清透半透明，拒绝写实油腻贴图。
5. 等距光影：正交等距视角（OrthographicCamera），配置带硬阴影（PCFShadowMap）的 DirectionalLight 与柔和的环境光。

【二、沙盒游戏性（汲取《我的世界》的核心要素）】
1. 角色与漫游：在沙盘上生成一个简易小巧的 3D 黏土小人（或小胶囊角色），实现键盘 WASD / 方向键移动，平滑贴合起伏地形高度，镜头跟随角色。
2. 动态生态世界：随噪声起伏自然生成的植被群落（圆冠阔叶树、高山针叶松、圆润的小石块、漂浮积雨云）；水体边缘轻微动态浮动。
3. 动态时间与环境：提供动态太阳方位或自动昼夜流转逻辑，展现阳光拉长时沙盘阴影切面的玩具美感。
4. 界面交互：左上角保留精致的新粗野主义（Neo-Brutalism）控制面板，包含：重新生成种子、描边开关、自转/跟随视角切换、日夜时间滑块。
