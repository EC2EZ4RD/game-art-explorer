### 0.2 HUD 为什么看着粗糙（给用户的直白解释）

1. **画框形状和大小不对，这是主因。** HUD 按 960×540 设计，放大 2 倍就是 1080p。现在中间的 3D 视图是竖长的 768×839，HUD 只能以 0.8 倍显示，所以：
   - 设计画布被拉成 960×1049，元素全被挤到四角，中间空着；
   - 正文 10.4px，标签 8.5px，线条 0.8px，都只有真实游戏里大约 40% 的大小。
2. **默认显示的是回归测试样本，不是展示用的 HUD。** 布局为「跟随」时，画的是 M1 时期的 4 件套：一条没有数字的血条、只有一个点的小地图，还带一条多余的分隔线。
3. **亮场景上文字没有描边或衬底。** 我们的场景平均亮度 0.33，艾尔登法环只有 0.04。38 个皮肤里有 32 个不给文字加阴影，所以字直接压在天空上，对比度大约 2:1。
4. **图标是程序员占位。** 技能和状态图标都是 Unicode 符号（⚒ ⚡ ♨），粗细和风格不统一，还和资源栏的 3D 位图图标混在同一屏。
5. **字号层级太平，线条太细**，同一个皮肤里各组件的规则也不一致。全局默认的强调色是一个粉红色。
6. 占位块是灰色斜纹的「需素材」，场景本身也像白盒。

> 只把画框改成 16:9 解决不了问题（compare_frames.png 的 B 图证明了这一点）。所以 §8 的 P0 必须和画框同一周上线。

### 0.3 关键裁决（三份方案冲突处）

| 冲突 | 裁决 | 理由 |
|---|---|---|
| 两种模式 vs 三个焦点 vs 自动切换 | **保留「画面 / UI」两种模式**，以顶栏标签的形式出现。**「场景」是两种模式共用的上下文**，不算一种模式。在画框上点击只改右栏的选中对象，**不切模式，也不换左栏内容** | 用户熟悉画面 / UI；评审一致反对悄悄切换 |
| 重置怎么实现 | 记录「来源」（来自哪个场景、配方、皮肤），用同一个合成函数算出基线，与当前值比差异，得出改动。**不把 store 改成 Composition**（那要改 143 处写入） | 风险最低，2 天能交付 |
| 点卡片时清不清手动改动 | 换配方：画面键整体替换（今天就这样）。换皮肤：只清皮肤负责的样式键（`ownsKey('skin')`，含 `*@el` 样式），**保留元素位置和尺寸**。换场景：丢掉元素位置改动，保留画面和皮肤。每次都有「已清 N 项 · 撤销」提示，左栏标题处有「保留我的改动」开关（也可按住 Alt 点） | 治好「选了皮肤没反应」；M2 后请用户确认 |
| 点配方要不要换场景 | **从不换。**配方卡上提示「在『横版·洞穴』里最好看 ›」，用户点了才换 | 可预测；用户看的是**自己的场景**换了画风 |
| 名词 | 界面上只用 **场景 / 画面 / UI / 界面**，加上条目名「配方 / 皮肤」。禁用「情境、场地、游戏、焦点、origin」等词。25 个 3D 环境只在场景弹窗里以「换环境」出现 | 评审要求最多 3–4 个名词，且用用户自己的词 |
| 首屏 | 打开就是**配方图库**（用户夸过的）。画框下方有一条可跳过、不挡操作的「你的游戏更像哪种？」，含 6 个视角卡片 | 不在最快的路径前面加一道问题 |
| UI 模式下左栏要不要自动收起 | 选定场景后**收起一次**，变成 64px 图标栏，可用 📌 钉住不收。选中或拖动元素时**绝不改变布局** | UI 第一眼就能放大到 1.075 倍 |
| 画面模式下显示 HUD 吗 | 默认隐藏，用 👁UI 切换；UI 模式下总是显示 | 浏览画风时不被粗糙的 HUD 拖累 |
| 皮肤色板用整帧还是局部 | 用**局部裁切**：生命 + 快捷栏一带，按 1:1 显示，约 152×64。悬停时放大成整帧 | 128px 宽的整帧 HUD 根本看不清 |
| 文字预算 | 整屏默认 ≤600 字：左栏 ≤150、画框下 ≤100、右栏 ≤300、各栏条 ≤50 | 取三份方案的中间值 |
| A/B 对比 | 全局只有一个「对比」和一个 A 徽标（带 ×）。学习库里的 A/B 演示各用各的分屏，不占 A 槽 | 现在有三套机制共用一个清不掉的 A 槽 |

### 1.2 名词表（界面文案只用这些）

| 词 | 含义 | 例子 |
|---|---|---|
| **场景** | 品类 + 环境 + 镜头。带一套默认 UI 和一组界面 | 魂类·城堡、横版·洞穴、农场·俯视 |

| **UI** | 界面风格这一层，具体条目叫「皮肤」 | 暗金、羊皮纸、霓虹 |
| **界面** | 场景里的一个画面时刻或一屏 | 局内、Boss、背包、对话、商店 |

### 1.3 配方分类（借鉴 loopyhop 的结构，不搬它的图和文字）

- **6 个分类**（芯片上的短名在括号里）：
  - ① 像素与复古（像素）
  - ② 绘画与线条（绘画）
  - ③ 东方笔墨（东方）：我们独有，loopyhop 没有
  - ④ 平面与图形（平面）
  - ⑤ 形体与材质（材质）
  - ⑥ 光影与渲染（光影）
- **筛选维度**：感觉（36 种）、2D/3D、可实现度（● 实时 / ◐ 局部 / ○ 仅参考）。
- **44 张卡**：现有 29 个基础配方 + 从风格图谱近似值提升的 15 个新配方（见 §9 表）。
  - 10 个素材变体（如 冷压纸 → 水彩）不单独成卡，作为父配方配方卡里的「变体」芯片。
  - 4 个叠加效果（霓虹雨夜、剥落做旧、VHS、手绘特效）加时段，做成「叠加」一行，可配任何配方。
- **loopyhop 37 种风格的覆盖情况**：15 种直接可做，14 种用新配方近似，8 种做不出来，标成「仅参考」卡。仅参考的是：8-bit、16-bit、精细像素、橡皮管、哥特线描、手抄本、古典拼贴、黑绘陶。
- **数据新增字段**（`recipes.ts`）：`category`、`kind`（风格 / 变体 / 叠加）、`parent`、`bullets[3]`、`showcase{scene, overrides}`、`neighbors`、`uiFamilies`、`realtime`。

## 2 主要使用流程（目标点击数）

**F0 首次打开**
1. 打开时的状态：画面模式；场景为「探索·小岛」；配方「低多边形」（由 C 挑最好看的一个）；HUD 隐藏。
2. 画框下方：
   - 一条 3 步引导「① 点左边的图 ② 右边微调 ③ 切到 UI 选场景」；
   - 一条「你的游戏更像哪种？」：横版 / 俯视 / 棋盘 / 第三人称 / 第一人称 / 平面（卡牌·VN）。可以跳过，不挡操作；用户点了任何东西就消失。
3. 之后再打开：栏条上显示 6 秒「已恢复上次：水彩 · 3 小时前 · 新实验」。

**F1 找画面方向（1 次点击）**
1. 点一张配方卡，约 300ms 内画框更新，卡片出现选中描边。↑ / ↓ 键切换到相邻的卡。
2. 画框下方变成配方卡，内容是：
   - ① ② ③ 三条看点：悬停时右栏对应参数闪一下，点击滚动过去；
   - 像这些游戏：2–4 个，点击后作为对比 A 的参考图；
   - 配套 UI：2–3 个皮肤色板，点击后套上皮肤并打开 👁UI；
   - 变体、叠加；
   - 「在 X 场景最好看 ›」；
   - 📋 复制提示词。
3. 在右栏微调：改过的行出现 •↺，标签显示「画面 水彩 ·3」。
4. 点 ☆ 收藏，自动命名「水彩 · 改 3 项」，同时存缩略图。

**F2 给我的游戏配 UI（2 次点击到 Boss 界面）**
1. 点顶栏的「UI」标签，左栏变成场景图库。图库按视角分组：3D 自由 / 俯视 / 横版 / 棋盘 / 立绘卡牌 / 赛道 / 名作。
2. 点「动作·地牢」，一步撤销内完成这些：
   - 搭好环境；
   - 镜头按场景设定，2D 场景会锁定；
   - 设置品类、布局、内容包、默认皮肤，界面停在「局内」；
   - **画风保持不变**；
   - 左栏收成 64px 图标栏。
3. 画框下方出现界面胶片：局内 · Boss · 标题 · 暂停 · 背包 · 地图 · 对话 · 商店 · 结算 ·（▶流程）。点「Boss」。
4. 皮肤色板一行，第一个是「默认」，接着「配套当前画面」，然后是 7 个家族。点一个色板就换皮肤。

**F3 从名作开始**
1. 场景图库切到「名作」，点 Hades，套上它的画风、皮肤和界面列表。
2. 界面胶片的缩略图用原作截图，仅开发模式可见。
3. 对比 ▸ 对照原作：A 边放参考截图。

**F4 直接改 UI（见 §6）**
悬停生命条出现轮廓 → 点击后出现手柄和快捷条 → 拖到左上（吸附锚点）→ 拉角放大 → 快捷条「画法▾ 液体球」。用 ↺ 还原这个元素。

**F5 对比（≤3 次）**
1. 点「对比」：把当前状态钉为 A，栏条出现「A: 水彩 ×」。
2. 改任意东西后，画框左右分屏，中间拖动分割线；双击分割线回到 50%。
3. 若只有 UI 不同，左右两边都是实时画面；否则 A 边用截图。
4. 菜单里有：换成 A、清除 A、对照原作。

**F6 带走**
- 导出▾ 下面有：截图（只截画框，1920×1080）、美术提示词（内置体检）、风格说明书、参数 JSON。Godot 导出只在开发者模式里出现。
- 方向板：收藏的缩略图网格，带「保留 / 下次试」备注。

**F7 想知道为什么（按需）**
- 参数行的 ⓘ：一个弹窗，最多 2 行字，带「看原则 P-12 ›」和「扫一遍」。
- 📖 学习：打开大图网格。
- 原则 A/B 演示在画框上运行，演示提示条放在画框下方。

**画框公式**
`frameW = min(stageW − 24, (stageH − 36 − deckH − 16) × aspect)`，`frameH = frameW / aspect`。

- 画框是一个只靠 CSS `aspect-ratio` 调尺寸的稳定 host div。Engine 现有的 ResizeObserver 会跟着变，**不重新挂载 WebGL**。
- 画框比例已与设备比例一致（差 <0.01）时，`deviceAspect()` 返回 0，HUD 和 OUTPUT pass 不再加黑边，避免黑边加两次。
- `camera.letterbox` 保留为画面内的电影黑边效果。QA 图要重新出基准。

## 4 重置与撤销模型

### 4.1 机制：来源记录 + 统一合成 + 差值

```ts
// src/state/layers.ts（新）
interface Origin { scene: string|null; recipe: string|null; overlays: string[];
                   skin: string|null; uiWords: string[] /* keyword / theme / rcp.* */ }
artBase(o) = defaults ⊕ sceneArt(o.scene) ⊕ look(o.recipe)【场景镜头锁定时去掉 look 的镜头键】⊕ overlays
uiBase(o)  = 选择器：sceneUi(o.scene) ⊕ skin(o.skin) ⊕ uiWords；其他 UI 键 = 不设（跟随）
modified(k)：画面键 values[k] ≠ artBase[k]；UI 选择器 ≠ 基线；UI 非选择器键：只要设了就算改动
```

- `values` 仍是扁平的，引擎和 `resolveUi` 都不用改。
- `origin` 与 values 一起进入持久化、历史快照、收藏和导出。`baseRecipe` / `baseStyle` 并入 `origin.recipe`（风格图谱条目记作 `atlas:<code>`）。
- **所有「套用」都走同一个合成函数**：applyRecipe / applyStyle / applyApprox / 案例近似 / 复刻 / 套用场景 / 套用皮肤。这样不会出现某处写入和基线算法不一致、错标改动的情况。
- 感觉、微调、混搭写入的值算作普通改动。
- **测试**：每个配方、风格图谱近似、场景、皮肤、复刻套用之后，对应层的 `modified = ∅`。
- **层归属**（决定改动记在哪个标签的计数上）：

| 标签 | 哪些键算它的改动 |
|---|---|
| 场景 | game.*、锁定时的镜头键、uip.layout、cnt.pack、界面选择 |
| 画面 | 其余画面键 |
| UI | 样式改动：vis/col/typ/mo/ast 和 `*@el` 样式键；元素位置：el.<id>.screenAnchor / offset / scale / width / height / visibility、实例 #2/#3、cnt.elements |

### 4.2 每个重置控件清什么

| 控件（位置） | 何时可见 | 清掉 | 保留 |
|---|---|---|---|
| 行 ↺ / 双击标签（右栏每行） | 这一行有改动 | 这个键回到基线（UI 键改为不设）；悬停提示写明「回到 画面·水彩：0.6」 | 其他所有 |
| 组 ↺（分组标题） | 组内有改动 | 本组的键回到基线 | 其他所有 |
| **元素 ↺**（快捷条 + 元素标题） | 这个元素有键 | 不设 `^el\.<id>(#\d)?\.` 和 `@el\.<id>(#\d)?$`；删掉实例 #2/#3；cnt.elements 成员回到基线 | 其他元素 |
| **界面 ↺**（界面胶片卡 ⋯） | 这一屏有部件改动 | `cmp.*@tpl.<id>` | 其他界面 |
| **画面 ▾ 回到「水彩」原样（N）** | 画面层有改动 | 画面改动：画面键全部回到 artBase | 配方、场景、全部 UI |
| 画面 ▾ 不用配方 | 用了配方时 | recipe 和 overlays 清空；画面键 = defaults ⊕ sceneArt | 场景、UI |
| **UI ▾ 清样式改动（N）** | 有 | 所有 UI 样式键，含 `*@el` 样式、感觉值、知识面板写入的值 | 皮肤、元素位置、场景 |
| **UI ▾ 还原元素位置（M）** | 有 | 元素位置键、实例、cnt.elements | 样式、皮肤 |
| **UI ▾ 回到场景默认 UI** | 皮肤、风格词、选择器或任何 UI 键与场景默认不同 | skin 清空、uiWords 清空；**不设所有 isUiKey**（复用 main.tsx 里 applyReplicaScreen 的那一行）；再写入 sceneUi 选择器。没选场景时回到 START 默认 | 画面、场景 |
| **场景 ▾ 回到场景原样** | 场景层有改动 | 场景负责的键回到 sceneArt / sceneUi；界面回到「局内」 | 配方、皮肤 |
| 镜头复位（双击画框空白处，或场景▾） | 镜头被转动过 | OrbitControls 回到场景机位（属于视图状态，不进撤销） | — |
| 再点一次已选中的卡或色板；每组的第一个「默认」 | 该层已设置 | 这一层退回下一层：配方 → 不用配方；皮肤 → 场景默认皮肤；风格词 / 节日 → 无 | — |
| 感觉芯片（11 个） | 它的值全部吻合时显示为选中 | 再点一次，不设它写过的键 | — |
| **顶栏 重置▾** | 总在 | 4 项，每项带计数：重置画面 / 重置 UI / 重置场景 / **全部重新开始**。前三项分别等于上面画面、UI、场景标签的完整重置。全部重新开始 = 回到首屏状态，同时把视图状态重置（诊断、检查、冻结、A 槽、参考图、流程演示、选中、缩放 → 适应、画面模式下隐藏 HUD） | 收藏、方向板、我的游戏、图库筛选 |
| 视图▾ → 重置视图 | 视图状态有改动 | 缩放、设备、诊断、检查、冻结、专注、👁UI | 所有值 |

**规则**
- 每次重置是一次 `store.patch`，只占一步撤销。之后状态槽显示「已重置 UI（清 23 项）· 撤销」。
- 有改动时重置按钮**永不置灰**，永不出现「(0)」。
- ↶▾ 打开带标签的最近 20 步，例如「换配方：水彩」「拖动 生命条」。点任意一步就跳过去。

**选择时的语义（点卡片是否清掉改动）**

| 操作 | 清掉 | 保留 |
|---|---|---|
| 点配方 | 画面改动 | 场景、所有 UI |
| 点皮肤 | `ownsKey('skin', k)` 的手动样式 | 元素位置、内容 |
| 点场景 | 场景负责的键 + 元素位置 | 配方、画面改动、皮肤、UI 样式改动 |
| 点界面 | — | 只改界面选择 |

- 左栏标题处的「保留我的改动」开关（或按住 Alt 点）在任何选择时都可以保留改动。

### 4.3 状态分区与持久化

- **视图状态独立出来**（`src/state/view.ts`，每个标签页各存一份在 sessionStorage 的 `gae.view.v1`）：
  - 包括：diag、chk.*（chk.demo 除外，它变成界面 / 流程内容）、缩放、专注、设备、👁UI、编辑开关、冻结、A 槽、参考图、选中、左栏开合、各组展开状态。
  - 做法：注册表给这些键加 `view: true`。在 Viewport 订阅处 `engine.apply({...values, ...view})`。**不改 54 处读取方**。
  - 这些键不进持久化、历史、导出、收藏，也不进改动差值。
- **工作副本**：`{values, origin}` 存在每个标签页自己的 sessionStorage `gae.work.v2`，从此多个标签页不再互相覆盖。
- **上次会话**：localStorage `gae.last.v2`，只在提交时去抖写入，新开标签页时读取。
- **撤销**：最近 50 步存 IndexedDB（idb-keyval），刷新页面不丢。
- **迁移**：读到旧的 `gae.values.v1` 时，按 `origin = {}` 处理，所有非默认值都算改动，同时提示「新实验」。
- **恢复不再漏键**：`setMany` 增加作用域 `'art' | 'ui' | 'all'`。收藏恢复、⇄、导入用 `'all'`：精确替换 UI 键集合，丢掉快照里没有的动态 el.* 键。
- **知识面板写入**：原则、图谱、复刻里的「试一下」改成临时预览（draft 叠在 values 上，不存）。栏条显示「预览：原则 #23 · 采用 · 取消」。点「采用」后写成普通改动，带 • 并且可以重置。这样不会再出现知识面板写的值悄悄压过皮肤。

## 6 画布上直接编辑（Claude Design 式）

**事件模型（不需要切换工具）**
- 画框上方叠一层 `.edit-layer`：每个 `eng.hud.hits` 矩形对应一个透明 DOM 盒，盒子设 `pointer-events:auto`，层的其余部分是 none。
  - 鼠标在元素上：交给编辑层。
  - 鼠标在别处：照常转动镜头；锁定镜头的场景不能转。
  - 按住空格：在元素上也强制转动镜头。
- 拖动元素时，F 轨道提供的 `engine.setOrbitLock(reason)` 会暂停 OrbitControls。
- 盒子在 `hits` 换新时重建。坐标已按 unitK 换算，再除以视距缩放系数。
- 这一层只在 UI 模式下生效。画面模式下 HUD 不能点选，悬停时提示「到 UI 编辑 ›」。
- 🎯 点选按钮和 `.hud-pick-layer` 删掉。

**悬停与选中**
- 悬停：1px 强调色轮廓，加名签「生命条 · 左下」。
- 点击：2px 轮廓、8 个手柄、锚点小圆点；右栏切到这个元素，本屏元素列表同步高亮。
- 点空白处取消选中。
- 画布上的 `setHighlight` 虚线框只保留给导出用。

**拖动与吸附**
- 换算成设计单位 `u = px / unitK`（960×540）。
- 元素中心落在安全区的哪一个九宫格，就写入哪个 `el.<id>.screenAnchor`；剩余的偏移写入 `offsetX/Y`。偏移范围从 ±20% 放宽到 ±50%（`register.ts`）。
- 拖动时显示参考线：安全区框、三分线、中线、9 个锚点。吸附到其他元素的边缘放到 P2。

**缩放**
- 角手柄写 `el.<id>.scale`（0.3–2.5）。
- 盒状元素的边手柄写 `width / height`（0.05–1）。

**浮动快捷条**（36px 高，在选中元素上方 8px；靠近顶边时翻到下方；不遮住元素）

2. 大小
3. 显隐
4. 画法
5. 颜色
6. 圆角 / 描边
7. 更多（约 50 项）

今天锚点在第 17 行、大小在第 24 行。

**键盘**（只在选中了元素且画框有焦点时接管；否则 WASD 和方向键仍控制角色行走）
- 方向键微调 1 单位，Shift + 方向键微调 10 单位。

## 12 风险与不做的事

### 风险与对策

| 风险 | 对策 |
|---|---|
| 只改画框，用户仍觉得粗糙 | E 的 P0 与画框同一周上线；M1 交对照图 |
| 基线和「套用」的写法对不上，导致错标改动 | 所有套用都走同一个合成函数，并用不变量测试兜底 |
| 离屏 HudSystem 做不通 | 第 1 天验证；退路是预先烘焙 PNG。色板与画框可能略有出入（不经过 OUTPUT pass 的合成），可以接受 |
| 画面编辑撞上「UI 按场景」的模板屏（hits 为空） | 先「选中整个界面」，第 3 周补上部件 hits |
| 方向键冲突（角色行走） | 只在选中元素且画框有焦点时接管；Esc 交还 |
| Viewport 改造导致 WebGL 重建 | 画框 host 只用 CSS 改尺寸；ReadabilityOverlay、A/B 分割线、视距缩放、对比剪裁、命中换算一起搬进画框 |
| 画框和 HUD 各加一次黑边 | 比例一致时 `deviceAspect` 返回 0；QA 基准有意重新出 |
| DPR 2 掉帧 | 实测后自适应，超过 16ms 回退到 1.5 |
| 并行时 Vite 反复整页刷新、多标签页互相覆盖 | 先做 T0；A 的分标签页存储尽早上线 |
| 点卡片清掉改动太强势 | 每次都有撤销提示，有「保留我的改动」和 Alt；M2 请用户确认 |
| 2D 场景第 3 周才上线 | 首屏视角卡片和 2D 复刻改指向都等它们上线，不用替身 |
| 版权 | 真实截图只在开发模式；不复制 loopyhop 的图和文字，看点由我们自己写；图标全部手写，不需要署名页 |

### 本阶段不做

- Godot 验证、调试、迁移包改动（只藏进开发者模式，不维护）。
- 把 store 改写成 Composition（scene-first 的方案）。
- 画布点击时自动切换模式或左栏内容。
- 实时渲染「每个场景 × 每个配方」的缩略图（只用预先烘焙的）。
- 界面切换时的运镜。
- 点 3D 场景直接编辑（roleAt）、「说说想要的感觉」输入框、多选、吸附到其他元素。这些都放到 P2。
- 用 LLM 改 UI。
- 新的 AI 生成（P2，且要用户先同意）。
- 删除广度。857 个参数、227 种风格、85 条原则、361 个案例全部保留，2 次点击内能找到。
